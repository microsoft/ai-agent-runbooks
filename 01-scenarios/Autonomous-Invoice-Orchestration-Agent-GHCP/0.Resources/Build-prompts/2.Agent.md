# Build Prompt — Agent

Use the prompt box on the [Copilot Studio](https://copilotstudio.microsoft.com/) **Home** page to create the **Autonomous Invoice Orchestration Agent** with its model, instructions and tools. AI builds the agent, but it can reword the instructions, skip a tool or leave a tool input unset. This page therefore covers how to run the prompt, what to check afterwards, and how to fix the **CreateSharingLink** tool by hand. The two skills named in the instructions are **not** created by the prompt. You upload them after the agent exists.

Create the Dataverse solution, the **Auto Invoice Review** table and the environment variables first (see Step 1-2 of the [Runbook](../../3.Runbook.md#step-1-2-create-the-dataverse-solution-table-and-environment-variables) and [Build Prompt — Dataverse Table](1.Dataverse.md)). The agent reads the environment variables and writes to that table.

## Create the agent with Copilot

### Run the prompt

1. Sign in to [Copilot Studio](https://copilotstudio.microsoft.com/) and select the environment from [Step 0-1](../../3.Runbook.md#step-0-1-create-power-platform-developer-environment) of the Runbook.
2. On the **Home** page, paste the prompt from [Copy-ready prompt](#copy-ready-copilot-prompt) into the input box and select the arrow to submit it. Copilot Studio opens a full-page chat and builds the solution there.
3. Answer any clarifying question so that it matches the prompt. Ask for **one agent only**, with no workflow, no knowledge source and no skills. This scenario builds the workflow separately in [Step 2-6 of the Runbook](../../3.Runbook.md#step-2-6-build-the-workflow-invoice-intake-and-approval).
4. If Copilot Studio asks for a connection for SharePoint or Dataverse, sign in with the service account. Do not use your personal account or the email sender's account.
5. When the build finishes, the agent appears as a card in the chat and in the **Artifacts** section of the side panel. Select the **Open** icon on the agent card. If the chat also created a workflow card, select **...** on that card and then **Delete workflow**.
6. Continue with [Check the agent](#check-the-agent). Do not publish yet.

### Check the agent

Open the agent and select the **Build** tab. Work through every row. If something is wrong, fix it by hand as shown in the last column. Do not send the builder another prompt, because it can rewrite parts that were already correct.

| # | Check | Where | Expected | If it is wrong |
| --- | --- | --- | --- | --- |
| 1 | Only one agent was created | Agents page, and the **Artifacts** list in the chat | One agent named exactly `Autonomous Invoice Orchestration Agent`. No extra agent, no workflow | Delete the extra artifact from its card menu. Correct a wrong display name in **Agent settings** |
| 2 | Model | **Model** list in the components panel | **Claude Sonnet 5** | Select it from the list and **Save**. If it is not listed, your region or tenant settings do not offer it. Choose an approved model and record which one. See [model availability](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/authoring-agent-model-availability) |
| 3 | Instructions | **Instructions** section | The text from `You are the **Autonomous Invoice Orchestration Agent**` to the closing `}` of the JSON object. It names both skills `invoice-extraction-review` and `save-invoice-json-to-sharepoint` and the **Auto Invoice Review** table. The JSON has exactly 10 keys: `invoiceKey`, `vendorName`, `currency`, `totalAmountDue`, `dueDate`, `decision`, `issues`, `summary`, `sourceLink`, `reviewLink`. The keys are camelCase, with no underscores or backslashes | Copy the text between `INSTRUCTIONS` and `TOOLS` from the prompt above, replace the whole **Instructions** section and **Save**. This also restores the exact skill names |
| 4 | No skills were created | **Build > Skills** | The list is empty | Delete any skill the builder generated. You upload the real skills next, and a second skill with the same name would be ambiguous |
| 5 | Tools | **Build > Tools** | Exactly three tools: **SharePoint MCP**, **Dataverse MCP** and the SharePoint action **CreateSharingLink**. No email, approval or workflow tool | Remove extra tools with the **X** next to them. Add a missing one with **Tools > Add a tool**. Use the **Model Context Protocol (MCP)** filter for the two MCP servers and the **Connectors** filter for SharePoint |
| 6 | Tool access | Each tool's details | Each tool is connected with the service account, and the data policy does not block it | Re-authenticate the tool. If a tool is greyed out in **Add a tool**, hover over the cross icon to see the policy that blocks it, and ask the administrator |
| 7 | CreateSharingLink inputs | **Tool details > Inputs** | The five values in [Configure the CreateSharingLink tool](#configure-the-createsharinglink-tool) | Set them by hand, as described below |
| 8 | Optional features are off | **Build** and agent settings | No web search, memory or other personal-context source | Turn the feature off |

### Configure the CreateSharingLink tool

Builders often leave a tool input empty or fill the wrong value. Always compare the tool with this table.

1. On the **Build** tab, select **CreateSharingLink** in the **Tools** list. The **Tool details** dialog opens.
2. In the **Details** panel, set **Name** to `CreateSharingLink`.
3. In the **Inputs** panel, set each input as in the table. **Fill with AI** lets the agent decide the value from the description at run time. **Custom** sets a fixed value that the agent cannot change.

   | Input | Setting | Value |
   |---|---|---|
   | Site Address | Fill with AI | `Get current value of environment variable or default value if current value is not set. Environment value displayname is SharePointSiteURL` |
   | Library Name | Fill with AI | `Get current value of environment variable or default value if current value is not set. Environment value displayname is SharePointDocumentLibrary` |
   | Item Id | Fill with AI | `File item id` |
   | Link Type | Custom | `View Only` |
   | Link Scope | Custom | `People in your organization` |

4. Select **Save**.

The agent finds the site address and the library name through the **Dataverse MCP** tool, from the `SharePointSiteURL` and `SharePointDocumentLibrary` environment variables. Both variables must exist in the solution, as in [Step 1-2 of the Runbook](../../3.Runbook.md#step-1-2-create-the-dataverse-solution-table-and-environment-variables). The Dataverse connection needs read access to the environment variable tables.

The link is **View Only** and limited to **People in your organization**. If your SharePoint administrator has turned off organization-wide links for the site, the tool fails. Ask the administrator before you change the scope.

### Confirm the solution

1. Open [make.powerapps.com](https://make.powerapps.com/), select **Solutions** and open **Autonomous Invoice Orchestration**.
2. Confirm that the **Autonomous Invoice Orchestration Agent** is listed. If it is not, select **Add existing**, choose the agent type and add the agent, so that it moves with the table and the workflow.

## Next step: upload the skills

The prompt creates no skills. Upload `invoice-extraction-review` and `save-invoice-json-to-sharepoint` from their `SKILL.md` files, as described in [Skills README — Import](../Skills/README.md#import). Do the first Preview test only after both skills are listed under **Build > Skills**.
