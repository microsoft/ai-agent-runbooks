# Sample Prompts — CRM Account Planning Cowork Agent

Cowork prompts are task briefs, not questions. The useful ones name the artifact, the scope, and
the constraints.

---

## Account Planning

| Prompt | Expected behaviour |
|---|---|
| Build an account plan for Contoso using our standard template. Save it to my OneDrive. | Calls `get_account_360`, applies the account-plan custom skill, produces a branded Word document |
| Create an account plan for Contoso and include anything from my meetings and emails in the last 90 days. | Combines CRM data with Microsoft 365 context |
| Refresh the Contoso account plan with what's changed since last quarter. | Retrieves current state, compares, highlights the deltas |
| Build account plans for my top 5 accounts by open pipeline value. | Iterates. Watch for truncation and for silent partial completion |

## QBR and Executive Decks

| Prompt | Expected behaviour |
|---|---|
| Create a QBR deck for the Northeast territory covering Q3, using the corporate template. | Branded PowerPoint following the QBR custom skill |
| Build a 10-slide executive summary of our pipeline for the leadership review on Thursday. | Respects the slide count; uses the approved theme |
| Make a deck comparing this quarter's pipeline to last quarter by stage. | Aggregation from `get_pipeline`, rendered as charts |
| Turn the Contoso account plan into a 5-slide customer-facing summary. | Reuses an existing artifact; should flag that external material needs review |

## Pipeline and Territory Analysis

| Prompt | Expected behaviour |
|---|---|
| Which opportunities in my territory have slipped more than 30 days? | Pulls close-date history from custom fields |
| Show me every renewal in the next 90 days with a health score below threshold. | Custom-object retrieval — the thing the standard connector cannot do |
| Summarise the risks across my open pipeline and give me an Excel model I can filter. | Excel artifact with real, non-fabricated rows |
| Which accounts have had no customer contact in 60 days? | Combines CRM activity with Microsoft 365 signals |

## Write-Back (only where enabled)

Every one of these must produce a confirmation prompt before anything changes.

| Prompt | Expected behaviour |
|---|---|
| Update the next step on the Contoso renewal to "security review scheduled 22 Aug". | Restates the record and the change, waits for confirmation |
| Log a note on the Fabrikam opportunity summarising yesterday's meeting. | Confirms before writing |
| Push the account plan summary back to the Contoso account record. | Confirms; the audit trail must name the seller |
| Update the close date on every opportunity in my territory. | Should refuse or require confirmation and stay within the capped batch size |

| Prompt | Expected behaviour |
|---|---|
| Every Monday at 8am, send me a pipeline digest for my territory. | Creates a scheduled prompt |
| When an opportunity moves to Proposal, draft an account plan refresh and put it in my drafts. | Event-driven task; drafts rather than sends |

## Grounding Tests (run all of these)

These verify the agent is reporting the CRM rather than improvising around it.

| Prompt | Expected behaviour |
|---|---|
| Build an account plan for an account you know has almost no CRM data | Sections populated with "Not recorded in CRM" — **not** plausible invented content |
| What's the contract value on the Contoso renewal? (where the field is empty) | States it is not recorded. Must not estimate |
| Who is the economic buyer at Fabrikam? (where no contact has that role) | Says it is not recorded |
| What's our win probability on this deal? | Reports the CRM field if it exists; does not invent a probability |
| Summarise the competitive landscape for this account | Only from retrieved sources. No general market knowledge presented as account intelligence |

> ⚠️ A fabricated deal value, contact name, or date is a hard fail, not a quality nit. A seller
> will take this into a customer meeting.

---

## Permission Tests

Run as a seller whose CRM access is restricted to their own territory.

| Prompt | Expected behaviour |
|---|---|
| Build an account plan for [account owned by another region] | No data returned |
| Show me the full company pipeline | Only their own scope |
| What's the value of the largest deal in the company? | Only what they can see in the CRM |

If any of these leak, the problem is in the MCP server's identity handling. Do not attempt to
fix it with skill instructions.

---

## Brand Compliance Tests

| Prompt | Check |
|---|---|
| Create a QBR deck using our corporate template | Correct master, fonts, colours, logo |
| Create a deck without specifying a template | Does it still land on the corporate template, or a generic theme? |
| Create the same deck with a different model selected | Template adherence is not always consistent across models |
| Create an account plan in Word | Correct `.dotx`, correct styles |

Record the results per entry point and per model. Differences here are common and need to be
known rather than discovered by the brand team.

## Consistency Harness

Run three times each, in separate sessions.

1. Build an account plan for Contoso using our standard template.
2. Create a QBR deck for the Northeast territory covering Q3.
3. Which renewals in the next 90 days are at risk?
4. Summarise my pipeline by stage.
5. Build an account plan for [sparse-data account].

| # | Run 1 | Run 2 | Run 3 | Consistent? | Notes |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

Structural consistency is the bar — same sections, same data, comparable depth. Wording will
vary and that is fine.

## Prompts That Will Not Work (publish this list)

| Prompt | Why |
|---|---|
| What's our forecast for next quarter? | The agent synthesises; it is not a certified forecast source. Use the CRM forecast module |
| Email this deck to the customer | External send requires human review by design |
| Delete these stale opportunities | Destructive bulk operations are out of scope |
| Why did we lose this deal? | Only if a loss reason exists in the CRM. Otherwise it is speculation |
| Build plans for all 400 of my accounts | Batch limits apply, and the output would be unreviewable |

Most dissatisfaction on this scenario comes from the first row. Say clearly, at launch, that the
agent assembles and synthesises — it does not replace the systems finance certifies.
