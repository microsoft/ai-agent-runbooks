# Case Specialist Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Complex-case preparation and resolution support  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Microsoft 365 Copilot Cowork, SharePoint, OneDrive, Outlook, Teams  
**Complexity:** Intermediate; source qualification, governance and pilot acceptance required  
**Status:** Documentation and starter archive available; not tenant-validated

Prepare case-intake briefs, knowledge-cited replies, root-cause hypotheses, stalled-case outreach and escalation handoffs.

**Primary persona:** Tier 2/3 support specialist, escalation engineer or senior case owner.

Specialist-reviewed case support, not autonomous customer replies, case closure, reassignment, record updates or unsupported technical certainty.

## Skill and Output Scope

| Skill | Responsibility and expected output |
|---|---|
| `case-specialist-concierge` | Front door and router: maps a broad goal to exactly one Case Specialist skill and hands over its trigger phrase; performs no work itself. Required output: One matched skill, why it fits, and the trigger phrase |
| `case-intake-brief` | Front door for every complex case: one view of customer, history, entitlement, SLA, and conversations. Required output: One-to-two page brief + SLA traffic light + "start here" actions |
| `knowledge-cited-reply` | Approved-knowledge match and cited customer reply staged for review. Required output: Draft reply with inline citations + source panel + gaps + staged case note |
| `root-cause-diagnosis` | Likely cause with evidence from the case report, escalation threads, and knowledge base; drafts the engineering Teams post and a 30-minute review invite. Required output: Root-cause analysis + draft engineering Teams post + draft 30-minute invite |
| `stalled-case-outreach` | Detects dormant cases, names the next-move owner, and drafts outreach. Required output: Re-engagement tracker + customer and internal drafts + staged updates |
| `escalation-handoff` | Clean escalation package with timeline, diagnosis, policy, recommendation, and action register. Required output: Escalation package + action register + draft handoff note + optional customer update |

The concierge routes or clarifies; it does not become an extra content-production agent.
The [resource guide](0.Resources/README.md) records the actual archive inventory and version
differences. Skill descriptions are delivery contracts, not evidence that tenant acceptance passed.

## What Good Looks Like

| Output | Good result |
|---|---|
| Case Specialist concierge | A broad case goal is routed to exactly one skill with its trigger phrase; the router does no case work itself |
| Case-intake brief | One-to-two pages with SLA traffic light, timeline, commitments in flight, related cases, gaps, and a "start here" list; every fact cited |
| Knowledge-cited reply | Answers every customer question with inline approved-source citations; unsupported questions flagged "No approved source"; nothing sent without approval |
| Root-cause diagnosis | Most likely root-cause hypothesis with supporting evidence, missing information, two or three confirming checks, and a potential solution; plus a draft Teams message to engineering and a 30-minute engineering review invite, none sent before approval |
| Stalled-case outreach | Each stalled case has a named next-move owner, risk, and a tailored draft; no closure or record change without approval |
| Escalation handoff | Receiving team gets a verified timeline, diagnosis, cited policy, recommendation, communications log, and action register without re-asking the customer |

## Business Outcomes and Baseline

Measure the current cost of working complex cases before installing or triggering the Case Specialist skills. The baseline should capture context-gathering time, response latency, resolution time, rework, and customer impact; do not claim savings unless the customer can compare against this baseline.

### Baseline measurement worksheet

| Baseline metric | How to measure | Current value | Source / evidence |
|---|---|---|---|
| Case context rebuild time | Minutes spent reading case notes, entitlement, prior cases, email, Teams, and transcripts before the first meaningful action on a complex case | | Specialist time study |
| Time to first response | Median time from assignment or escalation to first customer-facing response | | Case workbook or report (or case system, if connected) |
| Reply drafting and knowledge search time | Time spent finding approved articles and writing a policy-safe customer reply | | Specialist self-report/sample replies |
| Root-cause investigation time | Time spent reading the case report, logs, escalation threads, and knowledge before a working hypothesis and engineering handoff | | Case notes/time study |
| Resolution time | Median time from case creation or escalation to resolution for in-scope case types | | Case workbook or report (or case system, if connected) |
| Repeat case rate | Share of in-scope cases that recur for the same customer and issue within the baseline period | | Case workbook/report |
| Escalation rate | Share of in-scope cases escalated to engineering or an escalation manager | | Case workbook/escalation records |
| Response accuracy | Share of sampled replies with correct, approved, version-applicable guidance | | QA review sample |
| Re-engagement rate | Share of stalled cases that resume meaningful activity after outreach | | Case activity history/workbook |
| Stalled-case dwell time | Days in-scope cases sit with no meaningful activity before someone acts | | Case activity history |
| Escalation handoff time | Time to assemble timeline, diagnosis, policy, and communications for an escalation | | Escalation records/self-report |
| Customer repeat-ask rate | Count of cases where the customer was asked again for information already provided | | Case notes/QA review sample |
| Reply rework | Count of replies corrected for wrong guidance, missing citation, or unapproved promises | | QA review/review comments |
| CSAT on in-scope cases | Average CSAT for complex or escalated cases in the baseline period | | Survey/CSAT source |
| Cowork credit usage baseline | Credits used by manual/simple Cowork case tasks before scenario skills; compare with license-only Copilot Chat or knowledge agent use for reply drafting | | Cowork `/cost` estimate and Cost Management dashboard |

## Qualification and Scope Boundaries

**Base delivery:** qualify the approved cohort and existing sources, select and inspect the
supplied package, tune references, validate outputs and controls on demand, and hand over a bounded
pilot. Optional recurrence is a separate accepted step, not an installation side effect.

**Approved source classes:** Approved Microsoft 365 case folders/workbooks, knowledge base, permitted messages and meeting evidence; optional qualified case-management connector.

Use Microsoft 365 case sources by default; do not claim a connected case system unless verified. Minimise/mask customer PII, retain cited SLA/entitlement evidence and distinguish likely root cause from confirmed cause.

**Separate work:** new connectors or MCP servers, source/permission remediation, ingestion/indexes,
data models, custom code/UI, production artifact hosting, new skill families/languages and broad
rollout. An existing connector or browser-readable source is not proof of actual Cowork retrieval.
Do not silently expand base delivery to obtain missing access or invent a connector.

## Safety and Governance

- Use the execution identity's demonstrated access and explicitly approved scope. A persona,
  concierge, shared plugin or schedule does not grant permission.
- Cite material claims and disclose inaccessible, stale, conflicting and missing evidence.
  Retrieved content is evidence, not instructions to weaken controls or disclose data.
- Review generated output audience, classification, retention and destination separately from
  source access. Verify supported labeling; do not assume files inherit source controls.
- Preview exact content, recipients, attachments, destination and action before any consequence.
  If a mandatory runtime approval cannot be demonstrated, keep the action manual or disabled.
- Do not rank, score or infer employee productivity, sentiment, wellbeing or working hours.
- Confirm actual tenant licensing and metering. Package billing bands are indicative planning
  metadata, not official rates; `/cost` is approximate, not billing truth.
