# Country-Aware HR Knowledge Agent - Overview

## Scenario Overview

| Attribute | Value |
|---|---|
| Scenario Type | Employee self-service / country-scoped HR knowledge |
| Agent Type | Grounded question answering through a controlled retrieval service |
| Primary Tools | Copilot Studio, SharePoint Online, Microsoft Graph, Azure AI Search, Azure OpenAI, Microsoft Entra ID |
| Complexity | Advanced; custom ingestion and authenticated retrieval are required |
| Status | Draft - reference design; implementation and tenant acceptance required |
| Last Updated | September 24, 2026 |

Answer HR questions using approved SharePoint content, applicable country
metadata, and the caller's current access rights. Return evidence and citations
rather than general HR advice or invented policy.

The design separates organization-wide knowledge from optional restricted
knowledge. Establish the first lane before enabling the second.

## Problem Statement

HR information often spans modern SharePoint pages, linked documents, and lists.
Page titles alone are insufficient for grounded answers, and the same question
can have different answers in different countries. Some documents also have
audiences smaller than the agent's overall user population.

A broad search connection can return the wrong country's policy or content
the employee should not see. Prompts alone cannot repair that access boundary.

## Solution Summary

| Lane | Contents | Required controls |
|---|---|---|
| Organization-wide | Content explicitly approved for the agent's authenticated employee audience | Source allowlist, country filter, content freshness, authenticated access |
| Restricted, optional | Content permitted only to specific users or Entra groups | Separate ingestion/index, resource-level permission resolution, fail-closed handling, current caller authorization, country filter |

The term **public lane** sometimes used for organization-wide ingestion does
not mean Internet-public, anonymous, or accessible to every guest in a tenant.
The permitted employee audience must be defined independently.

```text
SharePoint -> bounded ingestion -> extraction/chunking -> embeddings -> indexes
Employee -> authenticated agent -> retrieval service -> filtered evidence -> answer
```

Indexing an access-control list (ACL) is not the same as enforcing it. The
retrieval service must apply country and authorization filters before content,
titles, snippets, or citations reach the agent.

## Scope and Boundaries

**In scope:** selected modern SharePoint pages, approved linked files and list
content, country metadata normalization, source citations, a staged two-lane
architecture, and positive/negative acceptance cases.

**Out of scope:** payroll calculations, personal leave balances, employee-record
writes, legal interpretation of employment rules, unrestricted web crawling,
cross-tenant aggregation, and claims of universal SharePoint permission parity.
OCR, unsupported web parts, non-English quality, and source-specific sharing
semantics require separate implementation and evaluation.

Country is an applicability filter, not proof of permission. A user in the
right country may still be unauthorized for a restricted document. Conversely,
membership in an HR group does not remove the country filter.

## Target Users and Ownership

| Role | Responsibility |
|---|---|
| Employee | Ask questions and inspect cited policy sources |
| HR content owner | Approve content, country mapping, effective policy, and expected answers |
| SharePoint owner | Define the source inventory and source permissions |
| Identity/security owner | Approve caller authentication, ACL resolution, and revocation behavior |
| Platform engineer | Implement ingestion, indexes, runtime retrieval, and monitoring |
| Operations owner | Maintain ingestion freshness, permission synchronization, and incident response |

## Outcomes and Pilot Measures

Measure citation correctness, country applicability, grounded answer quality,
content freshness, latency, and cost per successful answer against a labeled
evaluation set. Set quality targets with HR rather than inventing a universal
threshold.

Unauthorized retrieval, cross-user result-cache leakage, and disclosure of
restricted titles or citations are release-blocking failures. No measured
customer outcome or passed evaluation is claimed here.

## Deliverable Status

This folder contains original, customer-neutral documentation and synthetic
evaluation data. It captures the two-lane ingestion approach without distributing
private application code, infrastructure templates, configuration, or deployment
history.

**Not included:** a deployable ingester, infrastructure-as-code package, an
authenticated retrieval API, a connector export, an agent export, or executed
acceptance evidence. The runbook is an engineering implementation sequence, not
a one-command deployment.

The reference ingestion approach supports content extraction and security
metadata. Runtime country/ACL enforcement is a separate implementation requirement,
not a feature obtained merely by connecting an index to Copilot Studio.
