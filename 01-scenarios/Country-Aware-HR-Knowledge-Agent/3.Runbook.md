# Country-Aware HR Knowledge Agent - Runbook

**Audience:** Platform engineer, HR content owner, and identity/security owner.
**Status:** Draft implementation guide; no deployment or tenant tests have been run.

## Prerequisites and Build Inventory

This is not a deployment script. Assemble the following approved implementation
artifacts before following the sequence:

| Artifact/access | Required outcome |
|---|---|
| Source inventory | Selected sites, pages, libraries/lists, owners, lane assignment, and approved audiences |
| HR content policy | Canonical country map, explicit global semantics, policy precedence, and expected answers |
| Azure environment | Approved region, quotas, budget, resource provisioning and role-assignment authority |
| Graph identity | Administrator-approved permissions and resource grants for the actual read/ACL APIs |
| Ingestion application | Reviewed extraction, chunking, embeddings, indexing, reconciliation, and error handling |
| Deployment definitions | Reviewed infrastructure and container/job configuration; none supplied in this folder |
| Retrieval implementation | Authenticated API/tool enforcing country, principal, tenant, and freshness controls |
| Copilot Studio | Suitable authoring/runtime licensing, authenticated channel, approved connectors/DLP |
| Test identities | At least two countries, an allowed restricted group member, and a nonmember |
| Operations plan | Refresh/revocation objectives, monitoring, escalation, rollback, and retention |

Do not copy private source repositories, populated parameter files, Terraform
state, exported credentials, or customer policy documents into this repository.
The [synthetic fixture](./0.Resources/evaluation-fixtures.json) is test data,
not an index import or an authorization implementation.

## Phase 1: Establish the Content and Identity Contract

1. Inventory exact sources and confirm the allowed audience of every source.
   Start with organization-wide content only.
2. Define an HR-owned mapping from source country labels to canonical values.
   Adopt `GLOBAL` only for explicitly global policies. Treat missing tags as an
   error, not global content.
3. Identify the authoritative caller-country source and how corrections are
   approved. Country-of-residence or an arbitrary profile field may not represent
   the applicable employment jurisdiction.
4. Specify which page layouts, web parts, file formats, lists, and calendars the
   ingester actually supports. Set link-domain, depth, file-count, and size limits.
5. Define policy freshness and conflict-resolution behavior, including retired
   policies and conflicting global/local guidance.
6. Define the permitted employee audience and deny guests or other tenants unless
   they are explicitly part of a separately reviewed design.

**Exit criterion:** HR and the identity owner agree on source scope, country
semantics, test identities, and intended results.

## Phase 2: Provision the Platform and Least-Privilege Access

1. Provision Azure AI Search, an embedding deployment, and a job host such as
   Azure Container Apps. Add a registry and Key Vault only where required.
2. Separate organization-wide and restricted index/job configuration. Keep the
   restricted job and retrieval path disabled during the initial pilot.
3. Prefer managed identities for Azure-hosted execution. If Graph access needs
   another credential mode, keep certificates/secrets in an approved secret
   store and document rotation; never place them in parameter files or images.
4. Assign Graph permissions with administrator consent and selected-resource
   grants where supported. Explicitly configure approved sites when restricted
   discovery cannot enumerate the tenant. Do not grant `Sites.Read.All` or
   write permissions merely to make an unexplained 403 disappear.
5. Grant the ingestion identity embedding access and Search data-write access.
   Use a deployment identity for index-definition changes where feasible.
   Give the retrieval identity read-only Search access.
6. Decide network connectivity per hop: job to Graph, embeddings, Search,
   registry and secrets; agent to retrieval API; API to Search. Validate DNS and
   actual network reachability for each. A private endpoint does not by itself
   make a SaaS agent or connector able to reach the service.
7. Set operational budgets/alerts and secure log access before ingesting HR data.

Document the service-level access implications if both indexes share a Search
service. Separate services/identities may be needed for stronger isolation.

## Phase 3: Implement and Validate Organization-Wide Ingestion

1. Read only approved source locations with a crawl manifest recording source
   identity, completeness, configuration version, and per-item errors.
2. Extract real page body text, not just title/description. Check representative
   text, flexible layouts, embedded links, and approved list entries.
3. Resolve only bounded, allowlisted linked content. Confirm that every item in
   this lane is available to the entire permitted employee audience; a link from
   a broadly readable page does not establish that.
4. Normalize country and page-type metadata. Preserve original source URL and
   parent provenance without replacing a file's identity with its parent's.
5. Chunk with a documented token budget and overlap; generate embeddings using
   the chosen deployment. Match vector dimensions in the index and query path.
6. Implement bounded throttling retries respecting service guidance, propagate
   exhausted failures, and inspect per-document indexing results. Partial upload
   success must not be reported as a complete refresh.
7. Upsert stable chunk identifiers and reconcile obsolete chunks only after a
   complete, successful enumeration of the approved source set. Source removals,
   source-filter changes, and moved items need explicit reconciliation.
8. Test extraction and metadata directly in Search with synthetic content before
   connecting the agent. Inspect body text, country, URL, and completeness.

Prefer a staging index and controlled cutover for schema changes or full rebuilds.
Deleting a live index is not a safe routine migration strategy. Never let a
limited test run purge documents absent only because of that limit.

The source approach separates ingestion execution from scheduling. Configure and
exercise the selected host's manual or scheduled trigger explicitly; do not assume
creating a Container Apps job automatically establishes the required refresh cadence.

## Phase 4: Implement the Authenticated Retrieval Tool

1. Implement an API/tool boundary that validates the caller and obtains trusted
   tenant, object ID, employee-audience membership, and country.
2. Expose a narrow question/search input and bounded result count. Do not let the
   model choose an index, provide identities/groups, or pass an OData filter.
3. Query organization-wide content only with the country/global predicate,
   `IsPublic = true`, and the implemented source/freshness gates.
4. Return only allowed evidence: title, short relevant passage, original URL,
   and supported applicability information. Keep credentials and ACL principal
   lists out of tool results.
5. Partition caches by effective access context and country, or avoid result
   caching until this is implemented. Revalidate on context changes.
6. Return distinguishable no-evidence and service-unavailable results. Neither
   condition authorizes broader search, ungrounded policy advice, or fallback
   to a less restrictive index.
7. Connect the authenticated tool to Copilot Studio, validate caller propagation,
   and use [bounded response instructions](./4.Sample-prompts.md).

**Exit criterion:** representative country questions return only applicable
evidence and citations; spoofed caller/filter inputs fail at the service boundary.

## Phase 5: Add the Restricted Lane Only If Required

1. Obtain approval for the restricted source set and permission model. Do not
   reuse broad ingestion scope by default.
2. Configure the ingester to resolve security metadata and fail closed on
   unresolved permissions. In compatible implementations these controls may be
   named `EnableSecurityTrimming` and `FailClosedOnUnresolvedPermissions`;
   configuration flags alone are not evidence of correct enforcement.
3. Resolve effective permission evidence for every resource, including linked
   files with different ACLs. Test supported Entra groups, direct-user grants,
   inheritance, and sharing cases. Quarantine unsupported models.
4. Remove or make unavailable previously indexed versions when authorization
   evidence becomes unresolved or the source moves to a more restrictive audience.
   Merely skipping the new version can leave an older permissive copy searchable.
5. Store ACL verification/expiry evidence and enforce the agreed maximum age.
   An expired ACL must not remain queryable during a permission-service outage.
6. Resolve the caller's current allowed user/group principal set, including
   applicable transitive groups and group-claim overage. Fail closed if that
   resolution is incomplete.
7. Combine country **AND** valid ACL **AND** matching principal conditions before
   returning any result. Follow the [architecture filter contract](./2.Architecture.md).
8. Prove the agent has no alternate direct/unfiltered knowledge path to restricted
   content. Limit direct Search read access to authorized service/operators.
9. Test caller-group removal separately from document-ACL changes and index
   refresh. Establish bounded cache/token behavior and a conversation-context
   policy for previously returned content.

Do not enable this lane until all denial and stale-data tests pass. If the
connector cannot securely carry caller identity and enforce these requirements,
keep it disabled and implement an appropriate authenticated retrieval boundary.

## Phase 6: Evaluate End to End

All entries below are **required expected results, not passed test evidence**.
Use the synthetic fixture's labels only in the lab; map them to dedicated test
identities and resources without publishing those mappings.

| Case | Expected outcome |
|---|---|
| US employee asks a policy question | Eligible evidence is explicitly global or US-applicable, not GB-only |
| GB employee asks the same question | Eligible evidence changes to GB/global; no reuse of US cached results |
| Missing caller country | No unfiltered search; context-resolution guidance |
| Missing document country | Not treated as global; content quarantined |
| Restricted US document, US employee outside allowed group | No body, title, snippet, URL, count, or existence disclosure |
| Restricted US document, authorized US member | Permitted evidence with a valid citation |
| Authorized group member in the wrong country | Country restriction still applies |
| Direct-user grant without any group memberships | Only explicitly granted, country-applicable content is eligible |
| Public parent links to restricted file | Child ACL enforced independently |
| ACL lookup fails for a formerly indexed document | Older searchable copy invalidated or blocked by the implemented freshness gate |
| User removed from allowed group | Denied within the approved identity/cache objective, independent of unchanged document group IDs |
| Document changes allowed group | Old principal access removed within the approved ACL-refresh objective |
| Partial crawl, limited run, or indexing failure | Alert/incomplete state; no false success or indiscriminate bulk deletion |
| Source document deleted or removed from scope | Obsolete evidence removed through complete reconciliation |
| Malicious instructions inside a document | Treated as quoted source data; no filter changes or tool escalation |
| No supporting policy or conflicting evidence | Explain absence/conflict and route to HR; do not invent entitlement |
| Search/embedding service failure | Controlled service error, no unrestricted fallback |
| User supplies another tenant/user/group or raw filter | Rejected or ignored as untrusted input; no boundary change |

Record expected versus actual evidence IDs, citation correctness, latency, and
pass/fail in a protected evaluation record. Include extraction coverage, actual
country/permission semantics, stale-content tests, and query paths on every
intended channel. Fixture consistency alone does not establish system correctness.

## Phase 7: Release, Operate, and Roll Back

Start with the organization-wide pilot. HR signs off content/answers; the identity
owner signs off caller and country controls; operations accepts monitoring and
recovery. Enable restricted content only after a separate authorization review
and successful acceptance evidence.

Monitor source completeness, extraction yield, chunk/index failures, embedding
throttling, content/ACL age, denies, latency, and spend. A successful process exit
is insufficient if sources or items were skipped.

| Failure | Action |
|---|---|
| Graph 403 | Check the specific identity, endpoint permission, and selected-resource grant |
| Titles present but answers empty | Inspect extraction output and supported page/web-part types |
| Wrong-country evidence | Check normalization and server-generated query filters; do not patch the prompt alone |
| ACL incomplete or stale | Disable/quarantine affected restricted retrieval, refresh safely, then rerun denial tests |
| Vector dimension mismatch | Reconcile model and schema using a staging rebuild and controlled cutover |
| Repeated 429 or partial indexing | Apply bounded backoff, tune batching/quota, and report incomplete refresh |

To roll back, disable affected retrieval/ingestion paths, preserve diagnostics,
and restore only a known-good content/configuration version whose permissions are
still current. A stale backup is not safe simply because it previously worked.
Re-enable after access/freshness checks. Remove only lab-created resources during
cleanup and follow the approved retention requirements.
