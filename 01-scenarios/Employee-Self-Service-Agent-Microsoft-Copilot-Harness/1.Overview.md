# Employee Self-Service Agent with Microsoft Copilot Harness - Overview

**Scenario Type**: Employee Experience (HR + IT self-service)  
**Agent Type**: Microsoft Copilot Studio knowledge-grounded agent with ServiceNow and Workday integrations  
**Harness**: Microsoft Copilot  
**Primary Tools**: SharePoint and ServiceNow knowledge; proposed delegated ServiceNow and Workday tools  
**Complexity**: Advanced  

## Scenario overview

Give employees one authenticated HR and IT front door: answer policy and troubleshooting questions from approved **SharePoint and ServiceNow knowledge**, then, when separately enabled, work with the employee's own **ServiceNow HR cases, ServiceNow IT incidents and Workday information**.

This is a standalone sibling design. The source describes several build options, not a delivered topic-based agent. This variant uses global instructions for knowledge/navigation and nine focused live-operation skills for the **Microsoft Copilot Harness inside Copilot Studio**, not Copilot CLI or GitHub coding agents.

**Implementation boundary:** This repository supplies the procedures and contracts, **not executable connectors, MCP servers or workflows**. Uploading skills does not create integrations or grant access. Live capabilities stay OFF until a supported Microsoft Copilot Harness integration is delivered and validated.

## Users and outcomes

| Persona | Need | Measurable outcome |
|---|---|---|
| Employee | Find the applicable HR policy or IT fix without portal hopping | Time to a correct cited answer, compared with a pre-pilot baseline |
| Employee with enabled transactions | Read own requests and HR information; make a specifically confirmed change | Authorized read accuracy and verified completion; no cross-user disclosure or duplicate writes |
| HR Operations | Consistent guidance and own-case visibility | Deflection for the top 25 question categories; source-owner review of failures |
| IT service desk | Useful incident descriptions and transparent status | Confirmed incident creation, description fidelity and fewer status-chasing contacts |
| Delivery, identity and system owners | Independently enable capabilities without widening access | Signed capability manifest and positive/negative authorization evidence |

These are measures to collect, not achieved results. Establish baselines before the pilot.

## Capabilities and scope

Use the [Scope and Readiness guide](0.Resources/Scope-and-readiness.md) to inventory sources and integrations, prioritize use cases, and confirm selected capabilities, ownership and readiness before configuration.

| Capability | Evidence / system | Boundary |
|---|---|---|
| Policy and IT answers | Approved SharePoint libraries and ServiceNow KB articles | Source-grounded, cited, country/effective-date aware; no personal entitlement calculation |
| Request navigation | Approved links retrieved from those sources | Link only; navigation does not submit a request or order a catalog item |
| ServiceNow HRSD | List own HR cases or submit a new case | Listing and creation are independent. Creation requires confirmed descriptions and a selected HR Service; no updates or attachments. |
| ServiceNow ITSM | Create an incident and list own incidents across states | Listing shows Number, State and Short Description. Creation requires confirmation of urgency, short and full descriptions, and the signed-in caller; no catalog orders, updates or attachments. |
| Workday reads | Own Cost Center and approved employee information; connector or MCP core-profile route, with requested home contacts/balances through MCP only | Exact Cost Center type. The connector returns only the requested profile fields; a general profile request may return up to seven. No duplicate lookup or cross-route fallback after OFF/denied/failed results. |
| Workday home phone | Update the employee's existing home phone number through one business-process event | Preserve untouched fields; explicit staging/submission approval; no add/delete or work-phone changes |
| Workday time off | Submit standard Time Off / Absence Table requests | Validate eligible type, dates, daily quantities/units, balance and overlaps; confirmation; submission is not approval |

The [matrix](0.Resources/Capability-matrix.md) lists the nine skills, dependencies and states. Knowledge answers and navigation need no separate skill; enable configured knowledge **after** source validation. Every live skill is optional and OFF initially; a knowledge-only pilot must be labeled as reduced scope, not a full implementation.

The runbook also describes how to connect the [Workday Sana Self-Service agent using A2A](3.Runbook.md#workday-sana-self-service-agent-integration-using-a2a-protocol). This optional integration is separate from the nine starter skills.

**Excluded from the starter scope:** SAP SuccessFactors; Leave of Absence; time-off approval/cancellation; HR-case and incident updates/attachments; Workday email updates; new phone creation or work-phone changes; specialist reads such as compensation, national IDs, passports, visas and emergency contacts; payroll calculations and payslips; benefits enrollment; compensation changes; manager/on-behalf-of access; bulk export; employee profiling; autonomous triggers; mail sending; provisioning; catalog checkout; legal, tax or medical advice. Grievances, termination, discrimination and compensation disputes receive only an approved human contact route; do not collect their narrative into ordinary tickets.

## Compatibility and deliberate changes

| Source behavior | Microsoft Copilot Harness behavior | Disposition |
|---|---|---|
| HR + IT front door, curated content, representative pilot | Same business purpose with SharePoint and ServiceNow KB knowledge | Retained |
| Multiple build options | One new Microsoft Copilot Harness agent; source choices remain useful | Standalone implementation |
| Portal links for requests | Navigation remains available independently of writes | Retained |
| Optional own-request status without a concrete live path | Own HR-case and IT incident lists | Re-expressed; no inference from the knowledge index |
| Broad HRIS knowledge, including SuccessFactors | Workday is live own-record access, not an HR-policy crawler | Changed to requested focus |
| Default no personal salary answer / no HR writes | No salary lookup. With the relevant skill enabled, an employee can submit their own HR case, update their existing home phone number, or submit a standard time-off request. | Deliberate scoped expansion; all live skills OFF by default |
| Case data excluded in source prompt examples | Optional own-case tools, never cases as searchable knowledge | Deliberate expansion |
| Legacy seat thresholds, language and channel assumptions | Tenant-specific host, licensing, language and channel validation | Not inherited as product guarantees |

## Included and not included

Included: five scenario documents, provenance and reference links, configuration guidance and references for integrating ServiceNow and Workday with Microsoft Entra ID and configuring the ServiceNow Microsoft 365 Copilot (Graph) connector, an [example source/integration and use-case planning workbook](0.Resources/Use-case-planning.xlsx), a nine-row capability matrix, integration binding requirements, nine individually uploadable runtime skills, and positive/boundary/composed acceptance cases. The workbook is a broader illustrative backlog: defer/not-select rows outside the current matrix.

Not included: execution of tenant-specific configuration changes, connector credentials, backend code, solution exports, deployments, sample personal records, or evidence of live tests. Configuration guidance is included; applying and validating it in the target environment remains the delivery team's responsibility. The [runbook gates](3.Runbook.md#release-gates) assign ownership for these gaps. Supplied tool names/paths remain unverified tenant bindings; home-contact, HR-case and absence data require explicit privacy review.
