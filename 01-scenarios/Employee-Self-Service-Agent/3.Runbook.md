# Step-by-Step Guide — Employee Self-Service Agent

> **Scenario**: One HR + IT front door in Microsoft 365 Copilot
> **Platform**: Microsoft 365 Copilot · Copilot connectors · SharePoint
> **Target Readers**: Delivery engineer, workplace architect
> **Estimated effort**: 4–6 weeks end to end, of which the agent build is a few days

---

## Prerequisites

| Requirement | Details |
|---|---|
| Microsoft 365 Copilot licences | For the target population; confirm seat count against programme thresholds early |
| M365 admin role | Connector deployment and agent management |
| HRIS admin | Integration account, API access, sandbox instance |
| ITSM admin | Knowledge base access, user criteria, integration account |
| HR business sponsor | Named individual accountable for content quality |
| Deflection baseline | Current ticket volume for the top questions — you cannot prove value without it |

---

## Phase 0 — Readiness (Week 1)

### Step 0-1. Qualify

Complete the qualification checklist in [1.Overview.md](1.Overview.md). If any answer is
unknown, that is the first work item. The most common late surprises are seat thresholds,
language expectations, and an HRIS that is not on the supported path.

### Step 0-2. Baseline the problem

Pull the top 25 HR and IT question categories by ticket volume for the last quarter. This
serves three purposes:

- It becomes the evaluation set in Phase 4.
- It tells you which content must be connected first.
- It is the only credible measure of deflection after go-live.

Record it as:

| Rank | Question category | Monthly volume | Answer exists in | Owner |
|---|---|---|---|---|

### Step 0-3. Content audit

Complete the content architecture table in [2.Architecture.md](2.Architecture.md). Flag:

- Domains with more than one authoritative source
- Scanned or image-only policy documents
- Content that only exists in a language other than the target answer language
- Content with no identifiable owner

Agree remediation owners and dates. **Do not start the build until this list has owners.**

> ✅ **Exit criteria for Phase 0:** qualification complete, deflection baseline captured,
> content audit signed by the HR sponsor.

## Phase 1 — Tenant and Connector Setup (Week 2)

### Step 1-1. Confirm tenant controls

In **Microsoft 365 admin center → Copilot → Agents & connectors**:

1. Confirm agents are enabled for the target population.
2. Note the current settings for agent creation and agent consumption — you will likely need
   these decoupled. See
   [Agent Governance & Rollout Control Plane](../../02-patterns/Agent-Governance-and-Rollout-Control-Plane/Agent-Governance-and-Rollout-Control-Plane-Runbook.md).
3. Record the baseline so you can prove what changed if behaviour shifts mid-project.

### Step 1-2. Deploy the ITSM connector

Follow the
[Copilot Connector Knowledge Onboarding runbook](../../02-patterns/Copilot-Connector-Knowledge-Onboarding/Copilot-Connector-Knowledge-Onboarding-Runbook.md).
Pay particular attention to HR-scoped knowledge bases — the service account needs the HR
content-reader role or restricted HR content can be indexed as world-readable.

### Step 1-3. Deploy the HRIS connector — in a sandbox first

This is the step most likely to fail, and failures here are rarely fixable by configuration.

1. Deploy against the HRIS **sandbox** tenant.
2. Run 20 representative questions.
3. Record the failure rate and the exact error text. A malformed-response or HTTP 400 pattern
   on a majority of attempts is a known integration-path failure mode, not a configuration
   mistake — escalate rather than retry.
4. Only promote to production once the sandbox failure rate is acceptable.

**Have a fallback ready.** If the HRIS connector is not viable in the project window, the agent
can still deliver value grounded on SharePoint HR content plus the ITSM connector. Design the
pilot so that this fallback is a reduced scope, not a cancellation.

### Step 1-4. Prepare SharePoint content

1. Confirm the HR and IT policy sites are indexed and permissions are correct.
2. Re-publish any scanned PDFs as text.
3. Archive superseded versions. "Policy_v3_FINAL_updated.docx" alongside "Policy_v3.docx" will
   produce contradictory answers.

## Phase 2 — Deploy the Agent (Week 3)

### Option A — ESS agent template

1. Submit the enablement request with tenant ID, seat count, HRIS, and ITSM details.
2. Complete the readiness assessment.
3. Configure the connectors against the template.
4. Confirm the supported language scope with the HR sponsor **in writing**. English-only by
   default is the most common source of late-stage disappointment.

### Option B — Custom agent

1. Create the agent in Agent Builder (or Copilot Studio if flow control or write-back is
   required).
2. Add knowledge: ITSM connector, HRIS connector, SharePoint HR and IT sites.
3. Turn off web search unless there is a specific reason to keep it.
4. Write instructions. Starting point:

```text
ROLE
You are the Employee Self-Service assistant for <Organization>. You help employees
with HR questions (benefits, leave, payroll, policies) and IT questions
(how-to, requests, support).

SOURCES
- Answer only from the connected HR and IT knowledge sources.
- If the answer is not in those sources, say so and point the employee to the
  relevant team. Never answer HR policy questions from general knowledge.
- Always cite the source document for every factual statement.

BOUNDARIES
- Do not calculate or state an individual's entitlement, balance, or pay.
  Direct the employee to the HR portal for anything personal.
- Do not give legal, tax, or medical advice.
- For anything involving termination, grievance, discrimination, or
  compensation disputes, provide the contact route and nothing else.

REQUESTS
- When the employee wants to do something (order equipment, request access,
  book leave), point them to the exact catalog item or form, with a link.
  Do not describe the process from memory.

LANGUAGE
- Reply in the language of the employee's question.

FORMAT
- Direct answer first, in one or two sentences.
- Then steps or detail as a short list.
- Then "Sources:" with the document titles.
```

The boundaries block matters more here than in any other scenario. An HR-facing agent that
freelances on a grievance question creates a real problem.

## Phase 3 — Pilot (Week 4)

1. Pick a **representative** pilot population, not the friendliest one. Include at least one
   group with country-specific content and one frontline group if they are in scope.
2. Share the agent with the pilot group only, and ensure the connector rollout audience matches.
3. Run for two weeks minimum.
4. Collect:
   - Every question asked (usage reporting)
   - Every thumbs-down, with the question text
   - Ticket volume for the baselined categories

---

## Phase 4 — Evaluate

### Step 4-1. Test against the baseline

Take the top 25 question categories from Phase 0. For each, write 2–3 real phrasings from actual
tickets — not idealised versions.

| # | Question (real phrasing) | Expected source | Result | Consistent over 3 runs? |
|---|---|---|---|---|

### Step 4-2. Test the boundaries

| Test | Expected |
|---|---|
| Ask for a personal leave balance | Redirect to HR portal, no invented number |
| Ask a grievance question | Contact route only |
| Ask something that has no answer in the content | Clean "I couldn't find that" |
| Ask a question about content the user cannot access | Nothing returned |

### Step 4-3. Test across licence types and populations

Run the same set as:

- A Microsoft 365 Copilot licensed user
- A Copilot Chat user, if they are in the target audience
- A user in a different country with country-specific content

Differences between these are expected and must be documented before rollout, not discovered
by users.

### Step 4-4. Decide

| Signal | Action |
|---|---|
| ≥80% of baseline questions answered correctly and consistently | Proceed to rollout |
| 60–80% | Content remediation sprint, then re-test. Do not scale a 70% agent |
| <60% | Stop. The problem is content topology or connector health, not the agent |

---

## Phase 5 — Rollout and Operate

1. Expand the agent audience and the connector rollout audience together.
2. Publish through the organization's agent store so the agent has an owner and a review record.
3. Announce with explicit scope: what it does, what it does not do, where to go instead.
   Unmanaged expectations produce thumbs-downs that look like quality failures.
4. Establish the operating rhythm:

| Cadence | Activity | Owner |
|---|---|---|
| Weekly (first month) | Review thumbs-down questions, triage content vs configuration | Delivery engineer |
| Monthly | Deflection metric against baseline | HR / IT ops |
| Monthly | Content freshness review for the top 25 categories | Content owners |
| Quarterly | Re-run the full evaluation set | Delivery engineer |
