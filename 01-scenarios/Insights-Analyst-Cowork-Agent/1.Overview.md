# Insights Analyst Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Recurring business reviews and decision support  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Cowork, existing Power BI/Fabric sources or Excel Online workbooks  
**Complexity:** Intermediate; governed data access and KPI validation are prerequisites  
**Status:** Documentation available; tenant readiness and pilot acceptance required

Business teams repeatedly assemble the same performance review from reports and workbooks.
This scenario uses data the user already has permission to access to produce consistent
reviews across Sales, Finance, Retail, Manufacturing, and Service. Cowork summarises
performance, explains source-supported changes, and highlights risks and proposed next steps.

The deliverable is a **review-ready Markdown narrative, KPI/variance tables and HTML dashboard**,
not a new BI platform, semantic model, or autonomous decision-maker. HTML is a generated review
artifact; hosting a production analytics website is not included.

## Six-Skill Scope

One concierge routes to **one consolidated skill per business function**, not a separate skill
per KPI. All five functions share the same source, period, evidence and output discipline.

| Skill | Scope | Typical measures, when present in the approved source |
|---|---|---|
| `fabriciq-business-analytics-concierge` | Clarify function, period, region/segment and source; route only | No KPI calculations or report generation |
| `sales-analytics` | Consolidated sales review | Current/prior revenue, pipeline value/coverage/stage movement, quota attainment |
| `finance-analytics` | Consolidated finance review; confidential by default | Margin, actual spend vs budget, actuals vs forecast |
| `retail-analytics` | Consolidated retail review | Sales, inventory/stockout risk, sell-through |
| `manufacturing-analytics` | Consolidated manufacturing review | Throughput vs plan, first-pass yield, defect and escape risk |
| `service-analytics` | Consolidated service review | Case volume, backlog/ageing, SLA attainment and breaches |

Use region, segment, product, account, plant, store or queue/team aggregates as approved.
This scenario does not rank employees or infer individual productivity or performance.

## Source and Recurrence Contract

- Bind each run to an **explicit, approved Power BI report, Fabric semantic model/dataset,
  or Excel Online workbook URL**. Do not guess, search for an alternative, or silently reuse
  a previous session's report.
- For Power BI/Fabric, the delivery materials use the Fabric IQ plugin path. Verify availability,
  approved configuration, and actual query access in the target tenant. Opening a report in a
  browser does not prove Cowork can query its measures.
- Existing measure definitions, permissions, row-level security (RLS) and sensitivity policies
  remain authoritative. Data/model repair and unsupported source integration are separate work.
- Default period is the **last complete Monday-Sunday week**, also for on-demand runs.
  Daily, weekly, monthly or quarterly recurrence is a scoped choice; fiscal calendars and
  explicit user overrides must be confirmed.
- A schedule may carry an approved source binding only if policy and the package support it.
  If the skill requires a fresh URL interactively on every run, stop for that input: do not
  claim unattended recurrence works.
- Scheduling covers approved draft preparation, not unattended publication, background alerting,
  data write-back, or automatic business decisions.

## Business Outcomes

Baseline analyst preparation, refresh verification, variance explanation and review effort,
period-close-to-readout latency, corrections and missed material variances. Compare the same
functions and reporting periods in the pilot, including usage costs and human review time.
Agree numerical improvement targets with the sponsor; training savings claims are not measured
customer outcomes.

## Qualification and Boundaries

| Qualify before delivery | Stop or separately scope when |
|---|---|
| Cowork, required skills and supported data tool are available | Tenant/plugin enablement is incomplete |
| Named source owner and authoritative measures exist | New ETL, semantic-model engineering or data remediation is needed |
| Exact source and actual query permissions are verified | Access requires an unapproved identity or unsupported connector |
| Audience, output classification and distribution are agreed | Generated artifacts would expose restricted rows |
| Customer can supply quota, budget, plan or comparison measures | Review would require invented values or undisclosed assumptions |
| Approved six-skill package is obtained and inspected | Only documentation is available; installation cannot yet proceed |

Base scope is configuration, source binding, validation and an agreed pilot. Third-party
Tableau/Qlik/Databricks sources, direct ERP/SQL/on-premises integration, custom code/connectors,
new models/indexes/UI, additional languages/skills and broad rollout are not included.
Broader training examples do not expand that boundary.

## Output Quality and Safety

Every report names its source, refresh/as-of time, period, filters, grain, units and gaps.
Use model-defined measures; approved derived calculations must be transparent and traceable.
Missing data is **unavailable**, not zero. Undefined percentage changes are not fabricated.
Distinguish observed contributions from causal hypotheses.

Finance outputs remain confidential unless an authorised owner explicitly approves otherwise.
RLS at query time does not automatically protect a copied HTML or document artifact after
sharing. Review each output's audience, access, sensitivity and destination before distribution.
