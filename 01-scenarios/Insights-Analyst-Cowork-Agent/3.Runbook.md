# Insights Analyst Cowork Agent - Delivery Runbook

**Audience:** delivery engineer, business-function owner, data/model owner, tenant administrator,
security and billing owners. This is configuration-first delivery, not a data engineering project.

## 1. Qualify Tenant and Business Readiness

Apply the [Cowork Enablement runbook](../../02-patterns/Cowork-Enablement/Cowork-Enablement-Runbook.md)
for tenant readiness, security, governance and shared platform tests, and use the
[skill delivery runbook](../../02-patterns/Cowork-Skill-Delivery-and-Scheduled-Reviews/Cowork-Skill-Delivery-and-Scheduled-Reviews-Runbook.md)
for the six-skill package.
Verify Cowork access, skill/plugin governance, billing controls and supported pilot surface.
For Power BI/Fabric, confirm the source-material Fabric IQ plugin route is available and
approved, then run an actual authorised query. For Excel, prove workbook/table retrieval.
Do not treat browser access as query acceptance.

| Owner | Required input |
|---|---|
| Sponsor/function owner | Pilot functions, audience, cadence, baseline and value target |
| Data/model owner | Exact source, measures, grain, period, refresh and reconciliation evidence |
| M365/Fabric administrator | Approved tool path, user permissions, plugin availability |
| Security owner | RLS personas, confidential data, output destinations and approval policy |
| Billing/support owners | Usage controls, alerting, incident and schedule ownership |

**Stop** if access, query support or authoritative measures are missing. Do not silently build
a new connector/model or substitute a different dataset.

Apply [Cowork Spending Policies and Cost Governance](../../02-patterns/Cowork-Spending-Policies-and-Cost-Governance/Cowork-Spending-Policies-and-Cost-Governance-Runbook.md)
to the approved function/cohort security groups. Verify effective policy, funding, policy and
per-user limits, alerts and the credit-request route. Include source retrieval, consolidated
reviews, HTML generation and intended cadence in the intensity estimate; use official Cost
Management reports for reconciliation. Platform acceptance does not prove Fabric IQ availability,
actual query access, KPI fidelity, RLS or output audience safety.

## 2. Define the Review Contract and Baseline

Choose one initial function and representative source; expand to the other functions only
after its data-quality checks pass. Define each function's consolidated review and unavailable
subreports. If the approved package includes all six skills, verify all declared names while
keeping unqualified function data paths outside accepted scope.

Use the [governed analytics checklist](../../02-patterns/Governed-Analytics-Review/Governed-Analytics-Review-Runbook.md)
to record source URL, query identity, period, comparison, filters, currency, grain, KPI measures,
denominators, materiality thresholds, refresh expectations and output audience.

Default to the last complete Monday-Sunday week. Confirm fiscal-calendar deviations rather
than inferring them. Record manual preparation, refresh checks, variance explanation and review
time, readout latency, corrections and cost; agree the pilot target before generating reports.

**Exit:** source-owner-approved contract and baseline.

## 3. Obtain, Inspect and Configure the Package

Select a published archive from the [resource guide](0.Resources/README.md), review its
packaging notes and obtain tenant approval. Verify `SKILL.md` and companion reference files for:

- `fabriciq-business-analytics-concierge`
- `sales-analytics`
- `finance-analytics`
- `retail-analytics`
- `manufacturing-analytics`
- `service-analytics`

Tune references for function/persona, measure definitions, periods, thresholds, output sections,
source-input procedure and safe-action rules. Do not permanently hardcode a report URL or
credentials in the skill. Keep business logic in the governed source.

Confirm one routing target per function, no concierge KPI calculations, confidential finance
handling and no employee scoring. Record package version and changes.

## 4. Install and Run On Demand

Use [Customize Cowork](https://learn.microsoft.com/en-us/microsoft-365/copilot/cowork/cowork-customize)
and the shared runbook for approved per-user or plugin distribution. Start a new session,
confirm skill discovery, and provide the exact approved source URL.

1. Ask the concierge to clarify function, period, segment and source.
2. Execute the selected function skill against a known period.
3. Reconcile values with the data owner using identical identity, refresh and filters.
4. Compare narrative, KPI tables and HTML: all must use the same validated values.
5. Validate finance confidentiality and each function's subreport coverage.
6. Run denied-access, missing-measure, stale-source and employee-ranking probes.

HTML remains a reviewed artifact. Use text risk labels, no credentials or hidden restricted
rows, and no automatic external publication. Office exports are optional and require separate
format/template checks; do not call a Markdown outline a generated deck.

## 5. Execute Acceptance Tests

These are proposed minimum release gates, not completed tenant test results. Agree numeric
tolerances per KPI, expected latency and value targets before evaluation.

| ID | Test | Pass criterion |
|---|---|---|
| IA-01 | Discovery and routing | Six names discoverable; function routes correctly; concierge does not produce KPIs |
| IA-02 | Explicit source | Missing URL requests input; no guessed, stale or substituted source |
| IA-03 | Query access | Actual permitted query works; denied user receives no data |
| IA-04 | KPI fidelity | All sampled KPIs match the authoritative source within signed tolerances; no silent measure changes |
| IA-05 | Period and filters | Last complete Monday-Sunday default and explicit overrides correct, including boundary dates |
| IA-06 | Sales | Revenue, pipeline and quota subreports present or explicitly unavailable |
| IA-07 | Finance | Margin, budget and forecast comparisons reconciled; confidential output handling demonstrated |
| IA-08 | Retail | Sales, inventory/stockout and sell-through present or gaps identified |
| IA-09 | Manufacturing | Throughput, first-pass yield and quality/escape measures use approved definitions |
| IA-10 | Service | Volume, backlog/ageing and SLA values reconcile |
| IA-11 | Missing/zero/stale data | Missing quota/budget not zero; zero denominator not invented percentage; freshness failure visible |
| IA-12 | RLS and artifacts | Two differently entitled personas see only allowed data; copied output audience reviewed separately |
| IA-13 | Narrative/dashboard | Tables and HTML agree; causal claims supported or labelled hypotheses; text risk labels included |
| IA-14 | Safety and approval | Employee-ranking probes declined; zero unapproved distribution or write-back |
| IA-15 | Recurrence and cost | Approved source/period preserved, failures visible, lifecycle tested, usage reviewed with billing owner |

Use [sample prompts](4.Sample-prompts.md). Store expected/observed results, source evidence,
reviewer and retest outcome in the approved workspace. Any access leakage, invented metric,
unreconciled material value or approval bypass blocks release.

## 6. Qualify Scheduled Preparation

Reconcile the package contract with the schedule: training asks for a URL each session;
the SOW allows configured or session-provided sources. Choose and document one:

- **Interactive:** require URL confirmation each run; remain on demand if unattended source
  input is unsupported.
- **Approved scheduled binding:** store the approved source reference with the schedule, not
  permanently in generic skill instructions, and validate actual execution under the owner.

Approve exact prompt, source, timezone, reporting/comparison windows, cadence, draft destination,
reviewer and pause conditions before creating the schedule. Test create/view/edit/pause/resume/
delete, duplicate prevention, source access loss, missed refresh and a period boundary.
Approval to schedule does not approve automatic future distribution.

If the engagement excludes all unattended execution, leave recurrence disabled even if the
platform supports it. Do not broaden the SOW through a technical configuration choice.

## 7. Pilot and Hand Over

Compare preparation-plus-review time, reconciliation corrections, material-variance coverage,
readout latency and usage against baseline. Expand only after function/data owners sign off;
a Sales pilot is not evidence that Finance or Manufacturing is validated.

Hand over approved skill/reference versions, source/KPI contracts, RLS tests, sample accepted
reviews, artifact classification/sharing rules, schedule inventory, cost reports, known gaps and
support escalation. Assign responsibility for changed measures, refresh incidents, access
revocation, updated packages and period rules.

To roll back, pause owned schedules, prevent unreviewed distribution, restore the approved
package/reference version, and revalidate in a new session. Revoke sharing through supported
controls and verify its effect; previously copied reports need separate handling.

Use [Pilot-to-Scale Validation Gates](../../02-patterns/Pilot-to-Scale-Validation-Gates/Pilot-to-Scale-Validation-Gates-Runbook.md)
with the shared platform results and IA acceptance matrix. Revalidate each newly accepted
function, source and RLS persona; do not average a failed KPI, access or approval gate into
an overall pass.

Record **expand, extend, pause, or stop** with the sponsor. Model/data remediation, new source
integrations, extra languages and new skill families remain separately scoped.
