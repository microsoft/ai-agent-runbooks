# Insights Analyst D365 ERP Cowork Agent - Delivery Runbook

**Audience:** delivery engineer, finance and supply chain report owners, finance and operations
system administrator, Power Platform administrator, tenant administrator, security and billing
owners. This is configuration-first delivery of a supplied package (package 1.1.3, adapted from the
author's *Cowork Insights Analyst (D365 ERP) Scenario Runbook*); it builds no new data model,
semantic model or connector.

## 1. Qualify Tenant and Business Readiness

Apply the platform work in this order, then continue with this runbook:

1. [Cowork Enablement runbook](../../02-patterns/Cowork-Enablement/Cowork-Enablement-Runbook.md):

2. [Cowork D365 Finance and SCM Plugin Enablement runbook](../../02-patterns/Cowork-D365-Finance-SCM-Plugin-Enablement/Cowork-D365-Finance-SCM-Plugin-Enablement-Runbook.md):
   Step 4 (shared foundation), Step 5 (Finance) and/or Step 6 (Supply Chain Management), Steps 7
   to 13, and PLG-003 and PLG-004 (Finance), PLG-007 and PLG-008 (Supply Chain Management) and

3. The [skill delivery runbook](../../02-patterns/Cowork-Skill-Delivery-and-Scheduled-Reviews/Cowork-Skill-Delivery-and-Scheduled-Reviews-Runbook.md)
   for the eleven-skill package, alongside sections 3 to 6 below.

## 2. Define the Report Contract and Baseline

Sign a one-page pilot boundary covering: pilot users, the approved environment and the URL users
will enter, the legal-entity codes, the reports in scope and their owners, which schedules run and
for whom, the snapshot location, and the rules: read-only, every email and every snapshot write
outside the session approved one at a time (no pre-approval; see section 6), no staff analytics
and no composite vendor score, skills never switch environment or company, definition changes only
through a package version bump.

| Where | What goes there | Who sets it |
|---|---|---|
| The prompt, including scheduled-prompt text | Legal entity code and environment URL; optional as-of date or period | Each user; the schedule owner writes scheduled prompts |
| `skills/<skill>/reference.md` | KPI definitions, thresholds (for example the material-variance threshold), snapshot and trend rule, optional preset environment URL | Package owner, once per customer; definition changes require a version bump |

Use the [governed analytics checklist](../../02-patterns/Governed-Analytics-Review/Governed-Analytics-Review-Runbook.md)
to record periods, comparison basis, currency, thresholds and expected values for reconciliation
against Dynamics 365 views. Configure the snapshot location from day one: without a prior snapshot,
a report cannot show movement.

Example scheduled prompt:

```text
Give me the daily cash position and liquidity report for legal entity [code] on [environment URL].
```

**Exit:** signed boundary, approved definitions and thresholds, and baseline.

## 3. Obtain, Inspect and Configure the Package

Select an archive from the [resource guide](0.Resources/README.md) and obtain tenant approval.
Verify `SKILL.md` and `reference.md` for:

- `insights-analyst-concierge`
- `cash-liquidity-pulse`
- `warehouse-fulfillment-pulse`
- `ar-aging-collections-pulse`
- `ap-payment-readiness-pulse`
- `inventory-health-pulse`
- `procurement-po-health-pulse`
- `production-planning-pulse`
- `pl-budget-variance-report`
- `close-readiness-analytics`
- `supplier-performance-report`

In a working copy:

1. Confirm or reset the thresholds, including the material-variance threshold in
   `pl-budget-variance-report`, and record that the KPI definitions are accepted as shipped.
2. Check the illustrative entities each skill reads against the environment's metadata, and record
   any renamed, missing or custom entities as a gap list; the skills report such gaps rather than
   substituting.
3. Optionally preset the environment URL in every `reference.md`, so users are asked only for the
   legal entity.
4. Keep every `SKILL.md` under 20,000 characters as a recommended authoring target for readability
   and editing speed; Cowork's actual platform limit is 1 MB per `.md` skill file (see [Upload a
   skill or plugin](https://learn.microsoft.com/en-us/copilot/cowork/cowork-customize#upload-a-skill-or-plugin)).
5. Bump the manifest version and record every change. Keep the plugin layout: `manifest.json`, the
   icons, `README.md`, `INSTALL.md`, `LICENSE` and the expanded `skills/` folders at the root of
   the ZIP, with no outer folder.

## 4. Install and Run On Demand

Choose one installation route per user:

- **A. Recommended: plugin package (tenant pilot).** Author-test first in Cowork (Customize >
  Plugins > Upload plugin, shared with Only you). An administrator then uploads the plugin ZIP in
  the Microsoft 365 admin center, targets the pilot security group and manages it under Agents >
  Tools. Cowork shows the plugin as **Insights Analyst_D365 ERP**.
- **B. Not recommended: upload and share skills.** Upload one ZIP per skill under Customize >
  Skills, then share with specific users. On updates, delete the old copy, upload and share again.
- **C. Not recommended: OneDrive.** Copy each skill folder to `/Documents/Cowork/skills/`; skills
  are discovered at the next session.

Routes B and C leave unmanaged per-user copies of the definitions; use them only for author
testing, and remove them before a user switches to route A.

Each user then switches on the Dynamics 365 ERP apps plugin, configures the Finance & Operations
connector from the **Sources & Skills** panel, selects the approved environment and completes the
sign-in once. Record the installation route, plugin state and environment per user.

Before any schedule exists, run each skill on demand in a new session, in this order:

1. `insights-analyst-concierge` (IA-V-01), so users can route themselves.
2. The two daily reports (IA-V-02, IA-V-11). They confirm entity mappings, record numbers, the
   session inputs and the follow-up question fastest, and start the snapshot history.
3. The five weekly reports (IA-V-03, IA-V-04, IA-V-07, IA-V-08, IA-V-10), reconciling at least
   one KPI per report with a Dynamics 365 view.
4. The three monthly reports (IA-V-05, IA-V-06, IA-V-09).
5. The permission, safety, entity-variance, snapshot, record-identifier and follow-up probes
   (IA-V-12 to IA-V-18).

## 5. Execute Acceptance Tests

These are the repository minimum release gates: proposed tests, not completed tenant test results.
The identifiers are the package author's original test IDs; IA-V-19 is updated for package 1.1.1; IA-V-20 is added for package 1.1.2; IA-V-02, IA-V-03, IA-V-04 and IA-V-15 are updated for package 1.1.3.

| ID | Prompt | Pass when |
|---|---|---|
| IA-V-01 | "What analytics can you run?" | One report recommended with its trigger phrase, cadence and the legal-entity reminder; no Dynamics 365 access |
| IA-V-02 | "Give me the daily cash position and liquidity report." | Asks once for legal entity and environment URL; balances and forecast computed; HTML delivered; one follow-up question; no write. **Forecast-precedence check (illustrative, not a reconciliation guarantee):** with a customer invoice that appears both as an open transaction and as one matching cash-flow forecast entry, the invoice is counted once from the forecast entry; if that invoice instead appears as several forecast entries referencing it, they are summed by source document before comparing, and the open transaction is still excluded, not added again; expected inflows equal the forecast total plus only the open transactions with no matching forecast entry at all, never the sum of both totals |
| IA-V-03 | "Give me the weekly AR ageing and collections report." | Ageing buckets (Not yet due, 1-30, 31-60, 61-90, 91+) are mutually exclusive and reconcile to the full open AR balance; DSO computed per `reference.md` or shown as "not computable" if its source is unavailable or sums to zero; top-10 overdue customers carry account numbers; no write |
| IA-V-04 | "Give me the weekly AP ageing and payment-run readiness report." | Ageing buckets (Not yet due, 1-30, 31-60, 61-90, 91+) are mutually exclusive and reconcile to the full open AP balance; DPO computed per `reference.md` or shown as "not computable" if its source is unavailable or sums to zero; match exceptions computed; due-ledger rows carry invoice numbers |
| IA-V-05 | "Give me the monthly P&L, trial balance, and budget vs actual report." | Variances respect the configured material-variance threshold |
| IA-V-06 | "Give me the monthly period-end close readiness report." | Blocker ledger ranked; no write |
| IA-V-07 | "Give me the weekly inventory health report." | Stock-level exceptions flagged per `reference.md` definitions |
| IA-V-08 | "Give me the weekly procurement and open-PO health report." | Late-PO and requisition rows carry identifiers |
| IA-V-09 | "Give me the monthly supplier performance report." | Vendor facts only; no composite vendor score anywhere |
| IA-V-10 | "Give me the weekly production and master-planning status report." | Late-order and shortage rows carry identifiers |
| IA-V-11 | "Give me the daily warehouse and fulfilment operations report." | Open-work and backorder rows carry identifiers |
| IA-V-12 | Low-privilege test user; user assigned only to an out-of-scope legal entity | Only permitted legal entities and records; permission gap stated, not worked around |
| IA-V-13 | Inspect one output for people and vendor safety | No ranking, rating or scoring of staff, and no vendor score beyond the named metrics |
| IA-V-14 | Inspect one output for entity-name variance | A missing entity is stated as a source gap, never substituted or guessed |
| IA-V-15 | Run the same skill twice, a day apart, for the same legal entity and environment URL; approve the first run's snapshot write, then run a third time and decline that write | First run states "No prior snapshot - trend not yet available"; second run shows a trend labelled with the comparison date because the legal entity and environment URL both matched the first run's snapshot; every write outside the session Output folder showed its path and file name and waited for approval; the declined snapshot stays in the Output folder with no copy elsewhere |
| IA-V-16 | Inspect the record columns | Every row shows a business number as plain text; no hyperlink, GUID or internal ID; header shows the URL and legal entity as entered |
| IA-V-17 | Answer the follow-up question with (1) Word | Exactly one question asked; the .docx has every section and the same rows as the HTML; no second query; never an empty file |
| IA-V-18 | Answer the follow-up question with (2) email to me | To is the tester only; subject "[report] - [legal entity] - [date]"; summary in the body; HTML (and Word) attached; nothing sent until approved; declining sends nothing |
| IA-V-19 | Answer the follow-up question with (3) scheduled run on `cash-liquidity-pulse`, then let it run twice | Schedule created only after approval, with legal entity, environment URL and "email the result to me" in the prompt text. Each run requests approval before emailing: approve the first, decline the second; the second report stays in the session Output folder and no email is sent |
| IA-V-20 | A sandbox and a production environment that share the same company code (for example USMF); run the same report prompt against each in the same conversation | The skill keys each snapshot by legal entity and environment URL, so the sandbox and production runs never match each other's prior snapshot even though the company code is identical, and their snapshots are never compared or combined; if the plugin's connected environment or legal entity cannot be confirmed before generating, emailing, or saving, the skill pauses and reports a source gap instead of producing the report |

Run IA-V-01 to IA-V-18 and IA-V-20 on demand first and IA-V-19 as the first scheduled run in
section 6. Use
the [sample prompts](4.Sample-prompts.md). Capture the side-panel **Skills** chips and the
Automations run log as evidence, and store expected and observed results with the reviewer and
retest outcome. Any Dynamics 365 write, email to another recipient, per-person output, invented
value or trend without a prior snapshot blocks release.

## 6. Qualify Scheduled Preparation

Scheduling is optional. Create schedules only after section 5 passes on demand, in this order so
that snapshot history accumulates before the monthly trends are reviewed:

| Report | Suggested schedule |
|---|---|
| `cash-liquidity-pulse`, `warehouse-fulfillment-pulse` | Working days, early morning |
| `ar-aging-collections-pulse`, `ap-payment-readiness-pulse`, `inventory-health-pulse`, `procurement-po-health-pulse`, `production-planning-pulse` | Weekly, Monday morning |
| `pl-budget-variance-report`, `close-readiness-analytics`, `supplier-performance-report` | Monthly, first working day |

1. State the legal entity and environment URL in each scheduled-prompt text. A report can create
   its schedule itself when the user answers the follow-up question with "a scheduled run emailed
   to me", after the user approves it.
2. Use **Activate and run now** for each first run with the report's persona present, for example
   Treasury for `cash-liquidity-pulse` and the Controller for `pl-budget-variance-report`.
3. Record the schedule owner per report and legal entity. Schedules run under the owner's identity,
   permissions and snapshot history, and are managed from **Automations**; the limit is 25
   scheduled prompts per user.
4. Test create, edit, pause, resume and delete, a missed run, loss of access and a period boundary.

### Email and snapshot approval

A pre-approval cannot be limited to one recipient run or one snapshot folder: Microsoft Learn
(*Use Copilot Cowork with Dynamics 365 ERP*, reviewed November 25, 2026) states that **Always
allow** covers similar actions for the rest of the conversation, and a schedule runs with its
owner's own access, which reaches more than the snapshot location. Package 1.1.3 therefore
requests approval for each action, and the pilot owner keeps that rule:

- **Emails.** The schedule owner approves each email after checking the recipient, subject and
  attachments. Until the owner approves, the report stays in the session Output folder and nothing
  is sent; a declined or unanswered send leaves no email.
- **Snapshots.** A snapshot stored outside the session Output folder shows the destination path and
  file name and waits for approval of that write only. A declined or unanswered write keeps the
  snapshot in the Output folder, and the next run states that no prior snapshot is available.
- Nobody selects **Always allow** or a "don't ask again" choice for these actions, and approval of
  the schedule or of an earlier send or write does not authorize the next one.

Change this rule only if Microsoft documents an approval limited to one destination and the tenant
verifies it; record the evidence and the security owner's sign-off in the pilot boundary first.

## 7. Pilot, Hand Over and Roll Back

Governance during the pilot:

- The plugin is visible only through the tenant upload targeted at the pilot group.
  Organisation-wide publication requests are declined during the pilot.
- Users approve every email and every snapshot write outside the session one by one; nobody
  selects **Always allow** for those actions.
- Purview captures Cowork activity under Copilot activities.

Review the run log weekly during the pilot and compare against the baseline:

| Measure | Target |
|---|---|
| Skill discovery across pilot users | 100% |
| Session inputs asked once per conversation and stated in every header band | 100% |
| Material ledger rows with a plain-text business number; no hyperlinks, GUIDs or internal IDs | 100% |
| Trend shown only where a prior snapshot exists | 100% |
| Missing entities reported as source gaps | 100% |
| Routing accuracy | 95% or more |
| People or vendor-safety violations in sampled outputs | 0 |
| Output delivery: HTML first, one follow-up question, Word never empty, email only to the user after approval | 100% |
| Scheduled runs delivered on time | 95% or more |
| Out-of-scope records in permission and legal-entity spot checks | 0 |
| Time measures, DSO, DPO and days to close | Captured at 30 and 60 days |
| Leader usefulness score (1-5) | 4 or more |

Score structure, honesty and usefulness monthly on a 1-5 scale (target 4 or more). The monthly
reports need at least two monthly cycles for a real MoM, YoY or days-to-close trend, so schedule
the 60-day sponsor review after at least two monthly runs.

Hand over the approved package version, definitions and thresholds, scheduled-prompt texts and
owners, the snapshot location, sample accepted reports, the entity gap list and known gaps. Assign
owners for the definitions, package version, schedules, snapshot store and plugin manifest.

Rollback:

- **Plugin:** Microsoft 365 admin center > Agents > Tools > plugin > Users > Block (new
  conversations only), then pause or delete schedules from Automations.
- **ERP integration:** turn the Dynamics 365 ERP apps plugin off for the pilot group, or remove
  the Cowork client from Allowed MCP clients on the environment, which stops every Cowork user
  there.
- **Snapshots:** keep or archive the snapshot history under the customer's retention decision.

### Run-state and rollback record

Record for each pilot user: installation route, package version, approved environment, legal
entities, schedule names and owners, snapshot location, last successful run, open issues and the
rollback action taken.

### Exit criteria

- [ ] Section 1 complete, including the modules in scope of the plugin enablement pattern
- [ ] User access U1 to U7 confirmed per pilot user; boundary signed; baseline captured
- [ ] Definitions and thresholds confirmed; data-read entities checked against the environment, with gaps documented
- [ ] Plugin deployed to the pilot group with route, state and environment recorded per user
- [ ] Schedules created in daily, weekly, monthly order with owner, prompt text and per-send and per-write approval evidence
- [ ] IA-V-01 to IA-V-19 passed with evidence
- [ ] Rollback paths documented; Purview capture confirmed
- [ ] Owners assigned for definitions, package version, schedules, snapshot store and plugin manifest
