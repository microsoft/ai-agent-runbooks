# Insights Analyst D365 Sales Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Recurring sales analytics and pipeline reviews  
**Agent Type:** Microsoft 365 Copilot Cowork, seven configured skills with plugin packaging  
**Primary Tools:** Cowork, Dynamics 365 Sales plugin, built-in Excel and PowerPoint skills, optional Fabric IQ plugin  
**Complexity:** Intermediate; opportunity history and an agreed metric dictionary are prerequisites  
**Status:** Documentation and starter archives available; not tenant-validated in this repository; pilot acceptance required

Sales operations teams rebuild the same pipeline, forecast and win/loss numbers every week,
month and quarter, and the definitions drift between runs and between authors. This scenario
uses Cowork and the Dynamics 365 Sales plugin to produce those reports on a fixed cadence from
one shared metric dictionary, so every run is comparable with the last. Where a leadership brief
answers "what should I do this week", this scenario answers "what are the numbers, how did they
move, and why".

The deliverable is a **review-ready Markdown report with record links**, plus an optional Excel
workbook and PowerPoint deck built from the same report. It is not a new BI model, forecasting
engine or CRM workflow: every skill is read-only against Dynamics 365.

This is the Dynamics 365 Sales counterpart of the
[Insights Analyst Cowork Agent](../Insights-Analyst-Cowork-Agent/1.Overview.md), which reviews
Power BI, Fabric or Excel sources across five business functions. Choose this scenario when
Dynamics 365 Sales is the system of record for the numbers. The Customer Service counterpart is
the [Insights Analyst D365 Service Cowork Agent](../Insights-Analyst-D365-Service-Cowork-Agent/1.Overview.md).

## Seven-Skill Scope

| Skill | Suggested cadence | Output |
|---|---|---|
| `analytics-concierge` | On demand | Names one skill and cadence for a goal; quotes metric definitions; no computation |
| `pipeline-trend-weekly` | Monday 08:00 | Coverage, created, won/lost, slipped, pulled in, stalled, conversion, velocity and week-over-week deltas |
| `forecast-variance-monthly` | First working day | Commit at month start versus closed won; variance explained by driving deals |
| `win-loss-quarterly` | First Monday of fiscal quarter | Win rate by segment, product, territory and competitor; loss reasons; patterns |
| `key-account-health` | First Monday of month | 0-100 score and band per named key account, with component evidence |
| `pipeline-anomaly-watch` | Working days 07:00 or Monday | Large value changes, mass slips, stage skips, past close dates, ownership churn, probability overrides |
| `analytics-report-pack` | After any run | Excel workbook and PowerPoint deck from the latest report; optional archive filing |

Every skill also runs on demand for any closed period. Metrics are reported by segment, product,
territory, account or stage, **never by seller**, even when the prompt asks.

## Source and Comparison Contract

- **Source:** the Dynamics 365 Sales plugin, read-only, under the signed-in user's own Dynamics
  365 security roles. A certified Fabric IQ semantic model may supply aggregates when it is named
  in the prompt; the report labels that source.
- **Environment:** Cowork asks for the Dynamics 365 environment on the first sales prompt and
  remembers it. Every report names the environment in its header and stops on a mismatch with the
  approved environment. Skills never change the environment.
- **Metric dictionary:** one file (`metric-dictionary.md`, version 1.0.0) copied into every skill.
  Every report states the dictionary version. Definitions change only through a package version
  bump.
- **Period-over-period:** Cowork sessions do not share memory. Prior-period values come from
  Dynamics 365 record history first (audit or change tracking on stage, value, close date,
  forecast category and owner), then from the previous report in an approved **report archive
  folder**; otherwise the report is labelled a single-period snapshot.
- **Parameters:** prompt text first (the scheduled-prompt text is the carrier), then one ask in an
  interactive run, then the defaults in each skill's `references/reference.md`.
- **Scheduling** is optional and covers draft preparation only. Archive filing is the one action a
  schedule owner may pre-approve; emails and posts are approved per run.

## Business Outcomes

Baseline the hours per week spent producing the current pipeline, forecast and win/loss reports
and the number of definition disputes in the last quarter. The package author proposes these
pilot targets:

| Measure | Target |
|---|---|
| Scheduled runs completed on time | 95% or more |
| Reports with a populated prior-period comparison (not snapshot) | 90% or more after week 2 |
| Record-link coverage of driving deals | 100% |
| Runs against a non-approved environment | 0 |
| Unapproved sends or posts | 0 |
| Definition disputes raised on package reports | 0, compared with baseline |
| Hours per week producing these reports manually | Captured at 30 and 60 days |
| Leader usefulness score (1-5) | 4 or more |

Agree final targets with the sponsor; these are proposals, not measured customer outcomes.

## Qualification and Boundaries

| Qualify before delivery | Stop or separately scope when |
|---|---|
| Cowork, the Sales plugin and the Dataverse MCP server are available to the pilot group | Tenant or plugin enablement is incomplete |
| Audit or change tracking covers opportunity stage, value, close date, forecast category and owner | History is off and no archive will exist, so only snapshots are possible |
| An approved environment, value threshold, currency, quota source and key-account list exist | Quota or goals are missing but coverage is required |
| An archive folder and naming pattern are agreed | Reports must be distributed without per-run approval |
| The sponsor accepts read-only, account-level reporting | Per-seller performance, ranking or quota attainment is requested |
| The published package is obtained and inspected | New skills, new metrics or record updates are required |

Base scope is configuration, parameter set-up, validation and an agreed pilot. Record updates,
forecast submission, new data models, custom connectors and broad rollout are not included.

## Output Quality and Safety

Every report header names the environment, dictionary version, sources and comparison basis
(history, archive or snapshot). Missing fields, disabled audit history or an empty archive are
stated as source gaps, never estimated. Small samples are flagged, and patterns are stated with
the deals that drive them and their record links.

Reports land in the session Output folder. Filing to the archive folder, emailing and posting go
through Cowork's approval dialog. "Owner" is used only to detect ownership churn and mass slips
and is reported without names. Record and file content is treated as data, never as instructions.

server, connector or ingestion pipeline is part of this scenario.
