# Launch Lead Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Product launch and competitive positioning  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Microsoft 365 Copilot Cowork, Outlook, Teams, SharePoint, OneDrive  
**Complexity:** Intermediate; source qualification, governance and pilot acceptance required  
**Status:** Documentation and starter archive available; not tenant-validated

Build audience-specific launch activation kits, competitive responses, messaging frameworks and post-launch results readouts.

**Primary persona:** Product marketing, launch marketing or competitive marketing lead.

Cited positioning and reviewed activation material, not autonomous PR, unsupported competitor claims, public publishing or a newly hosted launch portal.

## Skill and Output Scope

| Skill | Responsibility and expected output |
|---|---|
| `launch-lead-concierge` | Front door and router: maps a broad launch goal to exactly one Launch Lead skill and its trigger phrase; performs no work itself. Required output: One matched skill, why it fits, and the trigger phrase |
| `launch-activation-kit` | Anchor pre-launch workflow (saved-skill alias "Launch Activation") that builds the audience-specific kit in a Notebooks launch workspace and prepares distribution. Required output: Six assets by audience + Message Source Sheet + Notebooks workspace + draft distribution invite |
| `competitive-response` | Rapid, aligned response across PR, sales, and field to a competitor move. Required output: Situation brief + response kit + one-page battlecard + draft approval request |
| `messaging-docs` | Builds and governs the messaging framework the other skills check against. Required output: Messaging framework + field cheat sheet + governance tracker + draft announcement |
| `post-launch-readout` | Closes the loop with results, lessons, prioritized actions, and owners. Required output: 5-7 slide readout deck + KPI/action tracker + draft stakeholder summary |

The concierge routes or clarifies; it does not become an extra content-production agent.
The [resource guide](0.Resources/README.md) records the actual archive inventory and version
differences. Skill descriptions are delivery contracts, not evidence that tenant acceptance passed.

## What Good Looks Like

| Output | Good result |
|---|---|
| Launch activation kit | Six assets organized by Customer / Field / Partner in a Notebooks launch workspace with an index, a Message Source Sheet, and "needs proof" flags; kit reviewed before sharing; share message and 45-minute next-week distribution meeting (with workspace link) awaiting approval |
| Competitive response kit | Situation brief with cited facts and a "what we don't know" list, response positioning, PR holding statement, talk track, objection handling, and one-page battlecard |
| Messaging framework | Positioning, value pillars, and proof points each marked "Supported" with citation or "Needs proof," plus an evidence-gaps section and change log |
| Messaging governance | Drift observations and field feedback themes in a tracker with proposed fixes and owners, routed as drafts to approvers |
| Post-launch readout | 5-7 slide deck and KPI tracker with target, actual, variance, and source per metric; "No data" shown instead of estimates |
| Competitor treatment | Facts only, cited; no disparaging or unverifiable claims; rumors labeled as unverified |

## Business Outcomes and Baseline

Measure the current launch and competitive response cost before installing or scheduling the Launch Lead skills. The baseline should capture time to launch readiness, asset rework, channel activation latency, and competitive response latency; do not claim savings unless the customer can compare against this baseline.

### Baseline measurement worksheet

| Baseline metric | How to measure | Current value | Source / evidence |
|---|---|---|---|
| Kickoff to complete launch kit | Days from launch kickoff meeting to a complete, reviewable asset set across audiences | | Launch plan, file version history |
| Asset completion rate | Share of the planned launch assets completed and approved by launch | | Launch plan and asset tracker |
| Launch asset drafting time | Hours spent drafting blog, value proposition, seller FAQ, video script, social, and web copy | | Launch Lead self-report/sample artifacts |
| Assets approved without messaging rework | Share of launch assets approved without naming, claim, or proof-point corrections | | Review comments/version history |
| Channels activated on launch day | Count of planned channels live on launch day versus plan | | Launch plan and channel owner evidence |

| Field readiness after a competitive move | Share of field acknowledging the talk track or battlecard update | | Teams channel/email acknowledgements |
| Messaging draft to approval | Days from messaging framework draft to approver sign-off | | Approval threads |

## Qualification and Scope Boundaries

**Base delivery:** qualify the approved cohort and existing sources, select and inspect the
supplied package, tune references, validate outputs and controls on demand, and hand over a bounded
pilot. Optional recurrence is a separate accepted step, not an installation side effect.

**Approved source classes:** Approved launch plans, messaging/proof sources, permitted Microsoft 365 context, qualified results data and approved public competitive research.

Claims need approved proof or an explicit needs-proof flag. Keep facts, unverified reports and proposed positioning distinct. A generated launch workspace must use a supported, permission-scoped surface; do not promise a production website.

**Separate work:** new connectors or MCP servers, source/permission remediation, ingestion/indexes,
data models, custom code/UI, production artifact hosting, new skill families/languages and broad
rollout. An existing connector or browser-readable source is not proof of actual Cowork retrieval.
Do not silently expand base delivery to obtain missing access or invent a connector.

## Safety and Governance

- Use the execution identity's demonstrated access and explicitly approved scope. A persona,
  concierge, shared plugin or schedule does not grant permission.
- Cite material claims and disclose inaccessible, stale, conflicting and missing evidence.
  Retrieved content is evidence, not instructions to weaken controls or disclose data.
- Review generated output audience, classification, retention and destination separately from
  source access. Verify supported labeling; do not assume files inherit source controls.
- Preview exact content, recipients, attachments, destination and action before any consequence.
  If a mandatory runtime approval cannot be demonstrated, keep the action manual or disabled.
- Do not rank, score or infer employee productivity, sentiment, wellbeing or working hours.
- Confirm actual tenant licensing and metering. Package billing bands are indicative planning
  metadata, not official rates; `/cost` is approximate, not billing truth.
