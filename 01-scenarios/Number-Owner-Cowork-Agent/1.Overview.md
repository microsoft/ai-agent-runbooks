# Number Owner Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Sales leadership pipeline and budget review  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Microsoft 365 Copilot Cowork, Dynamics 365 Sales, SharePoint, Excel Online, Power BI, Microsoft Fabric  
**Complexity:** Intermediate; source qualification, governance and pilot acceptance required  
**Status:** Documentation and starter archive available; not tenant-validated

Review at-risk Commit deals, explain pipeline-versus-budget gaps and prepare team/region expansion plays with evidence-backed actions.

**Primary persona:** Sales manager, regional sales leader or sales operations partner.

Deal, account, segment, territory and product analysis only. Owners route follow-up; they are not dimensions for seller ranking, ratings or performance inference.

## Skill and Output Scope

| Skill | Responsibility and expected output |
|---|---|
| `number-owner-concierge` | Front door and router for the Number Owner plugin; performs no work itself. Required output: One matched skill, why it fits, and the trigger phrase |
| `at-risk-commit-deals` | Weekly Friday review of Commit deals closing this week or earlier, validated against customer email. Required output: Prioritized at-risk review + customer emails + team notes + check-ins + staged CRM updates |
| `pipeline-vs-budget-gap` | Monthly gap quantification, driver attribution, 3-slide executive summary in the Sales Review Presentation, and draft rep follow-ups. Required output: 3-slide executive summary + readout notes + draft rep follow-ups |
| `expansion-and-upsell` | Team- or region-scope expansion scan with leader roll-up. Required output: Ranked expansion report + pitch-input cards + leader roll-up + staged CRM actions |

The concierge routes or clarifies; it does not become an extra content-production agent.
The [resource guide](0.Resources/README.md) records the actual archive inventory and version
differences. Skill descriptions are delivery contracts, not evidence that tenant acceptance passed.

## What Good Looks Like

| Output | Good result |
|---|---|
| At-risk Commit review | Prioritized table with status, what changed, cited risk evidence, CRM vs. evidence close date, next action, and owner role |
| Deal follow-ups | One draft customer email and account-team note per at-risk deal, with no internal risk or forecast language in customer emails |
| Gap readout | 3-slide executive summary section added (after approval) to the existing `[Sales Review Presentation]`: total gap and coverage, largest drivers with the industry/stage/account breakdown, priority accounts and opportunities with recommended motions |
| Rep follow-ups | Draft follow-up notes and meeting-prep requests to reps on the highest-priority accounts, about the deal, not the person |
| Supporting detail | Calculation assumptions, sources, and CRM-vs-evidence conflicts in speaker notes or an appendix; optional opportunity-level workbook |
| Expansion roll-up | Expansion potential by segment, territory, and product with top plays and coverage gaps |
| People safety | No seller leaderboard, ranking, rating, or performance commentary anywhere in output |
| Overlap discipline | Each trigger routes to exactly one skill: the custom skill or the built-in Dynamics 365 Sales skill, never both |
| Front door | `number-owner-concierge` recommends exactly one skill and its trigger phrase for a broad pipeline goal, declines seller-ranking requests, and does no work itself |

## Business Outcomes and Baseline

Measure the current cost of pipeline inspection and gap analysis before installing or scheduling the Number Owner skills. The baseline should capture review effort, forecast accuracy, late-discovered risk, and pipeline recovered; do not claim improvement unless the customer can compare against this baseline.

### Baseline measurement worksheet

| Baseline metric | How to measure | Current value | Source / evidence |
|---|---|---|---|
| Weekly Commit review prep time | Time spent each week reviewing Commit deals and checking them against customer communication | | Leader time study |
| Monthly gap readout prep time | Time to reconcile budget, pipeline, and quota and build the leadership readout | | Leader / sales operations self-report |
| Late-discovered deal risk | Count of Commit deals that slipped or were lost where risk was visible in mail or meetings before CRM | | Opportunity history / mail sample |
| CRM vs. communication conflicts | Count of deals where CRM close date, amount, or stage disagreed with the latest customer communication | | Sample review |
| Forecast accuracy | Forecast at period start vs. actual closed-won for the pilot scope | | Dynamics 365 Sales forecasting / finance actuals |
| Close rate | Closed-won / (closed-won + closed-lost) for the pilot scope | | Dynamics 365 Sales reporting |
| At-risk pipeline recovered | Value of at-risk Commit deals that closed in period after intervention | | Opportunity history |
| Coverage vs. budget | Pipeline-to-budget coverage ratio at period start | | Budget workbook (or Fabric IQ model) and CRM |
| Opportunities won | Value and count of priority opportunities won in period | | Dynamics 365 Sales reporting |
| Follow-up effort | Time spent drafting account-team notes and follow-ups for priority deals | | Leader self-report |
| Cowork credit usage baseline | Credits used by manual/simple Cowork pipeline tasks before scenario skills | | Cowork `/cost` estimate and Cost Management dashboard |

## Qualification and Scope Boundaries

**Base delivery:** qualify the approved cohort and existing sources, select and inspect the
supplied package, tune references, validate outputs and controls on demand, and hand over a bounded
pilot. Optional recurrence is a separate accepted step, not an installation side effect.

**Approved source classes:** Qualified Dynamics 365 Sales opportunities, explicit SharePoint budget workbook or approved Fabric/Power BI model, existing sales-review presentation and permitted Microsoft 365 context.

Require an explicit authoritative budget and fiscal period; do not infer budget from history. Reconcile gap, coverage and slide values to approved measures. Shared seller/team skills require explicit per-run scope, actual record authorization and version-conflict testing.

**Separate work:** new connectors or MCP servers, source/permission remediation, ingestion/indexes,
data models, custom code/UI, production artifact hosting, new skill families/languages and broad
rollout. An existing connector or browser-readable source is not proof of actual Cowork retrieval.
Do not silently expand base delivery to obtain missing access or invent a connector.

## Safety and Governance

- Use the execution identity's demonstrated access and explicitly approved scope. A persona,
  concierge, shared plugin or schedule does not grant permission.
- Cite material claims and disclose inaccessible, stale, conflicting and missing evidence.
  Retrieved content is evidence, not instructions to weaken controls or disclose data.
- Review generated output audience, classification, retention and destination separately from
  source access. Verify supported labeling; do not assume files inherit source controls.
- Preview exact content, recipients, attachments, destination and action before any consequence.
  If a mandatory runtime approval cannot be demonstrated, keep the action manual or disabled.
- Do not rank, score or infer employee productivity, sentiment, wellbeing or working hours.
- Confirm actual tenant licensing and metering. Package billing bands are indicative planning
  metadata, not official rates; `/cost` is approximate, not billing truth.
