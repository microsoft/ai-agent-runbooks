# Procurement Operator Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Procurement and operations record preparation  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Microsoft 365 Copilot Cowork, Excel Online, SharePoint, Outlook, Teams  
**Complexity:** Intermediate; source qualification, governance and pilot acceptance required  
**Status:** Documentation and starter archive available; not tenant-validated

Stage master-data records, itemise expenses, prepare received RFQ responses, compare supplier bids and assemble regulatory evidence responses.

**Primary persona:** Procurement/sourcing lead, finance partner, master-data/AP specialist or operations coordinator.

The assistant prepares on behalf of the preparer and never acts as approver. No autonomous vendor creation, expense submission, payment, award, purchase order or regulatory filing.

## Skill and Output Scope

| Skill | Responsibility and expected output |
|---|---|
| `procurement-operator-concierge` | Front door and router: maps a broad procurement or operations goal to exactly one Procurement Operator skill and its trigger phrase; performs no work itself. Required output: One matched skill, why it fits, and the trigger phrase |
| `master-data-automation` | Governed customer, vendor, or product record preparation from requests and specs. Required output: Staging workbook + exceptions list + approval request draft |
| `expense-itemization` | Receipt itemization, card reconciliation, policy check, and draft expense entry. Required output: Itemization workbook + exception summary + draft expense entry |
| `rfq-response` | Structured response package for an RFQ we received. Required output: Requirements & pricing workbook + Word response draft + clarification and approval tracker |
| `bid-to-award` | Bid comparison across bids, vendor information, purchasing history (Fabric IQ), and evaluation-meeting decisions; supplier recommendation, comparison workbook, and manager review email; optional award drafts. Required output: Supplier recommendation + bid comparison workbook + manager review email |
| `regulatory-response` | Request-to-evidence mapping and item-by-item draft response for a regulator or agency. Required output: Item-by-item response draft + request-to-evidence matrix + exhibit index + approval tracker |

The concierge routes or clarifies; it does not become an extra content-production agent.
The [resource guide](0.Resources/README.md) records the actual archive inventory and version
differences. Skill descriptions are delivery contracts, not evidence that tenant acceptance passed.

## What Good Looks Like

| Output | Good result |
|---|---|
| Master-data record | Staging workbook in target-system field order, every value with source trace, Valid/Invalid/Missing validation, duplicate candidates, bank-detail flags, and approval request draft; no record created |
| Expense entry | Every charge itemized, line items sum to receipt, receipt ties to card transaction, each line marked Compliant or Exception with policy clause, and a draft entry; nothing submitted |
| RFQ response | Compliance matrix covering every requirement, pricing with formulas from the price list or ERP, terms deviations, clarifications, and approval routing plan; nothing sent |
| Bid-to-award (Supplier Analyzer) | Supplier recommendation document with preferred supplier, evidence, and major risks or tradeoffs; comparison workbook covering pricing, capabilities, delivery commitment, prior performance from [Purchasing History], strengths, weaknesses, and exceptions; review email to the manager linking both files; all shown before anything is shared; optional award or PO drafts only on request; no award or notification |
| Regulatory response | Each numbered item mapped to evidence (Evidenced/Partial/Missing), figures recomputed with formulas, consistency checked, and a back-scheduled approval tracker; nothing submitted |
| Procurement Operator routing | `procurement-operator-concierge` returns exactly one skill and its trigger phrase; RFQ response and bid-to-award are not confused |

## Business Outcomes and Baseline

Measure the current operating cost before installing or scheduling the Procurement Operator skills. The baseline should capture cycle time, rekeying effort, policy exceptions found late, bid-analysis effort, and rework. Do not claim savings unless the customer can compare against this baseline, and record each value with its calculation basis.

### Baseline measurement worksheet

| Baseline metric | How to measure | Current value | Source / evidence |
|---|---|---|---|
| Record creation cycle time | Median elapsed time from request received to approved record (approval timestamp - request timestamp) | | Request mailbox/list and ERP audit trail |
| Fields rekeyed per record | Fields manually typed from request documents into the staging template or ERP | | Sample of recent records |
| First-pass validation rate | Records passing data-standard checks on first submission / records submitted; clarification emails per record | | Data steward review log / mailbox sample |
| Duplicates found after creation | Count of duplicate records identified after creation | | Master-data quality report |
| Expense processing time | Minutes per expense report from receipts gathered to draft entry ready | | User time study |
| Policy compliance | Policy exceptions caught before submission / total policy exceptions (pre- plus post-submission) | | Expense system rejection history |
| Receipt-to-card match rate | Receipts matched to card transactions / total card transactions | | Card statement vs. expense report sample |
| RFQ response cycle time | Elapsed time from RFQ receipt to approved submission | | RFQ tracker / mailbox |
| Bids evaluated | Bids compared per sourcing event and per month | | Sourcing event files |
| Recommendation time | Hours from bid close to a supplier recommendation ready for manager review; elapsed time from bid close to award approval | | Sourcing event files / approval records |
| POs or award drafts created | POs or award drafts prepared per awarded event, and hours to prepare them | | Procurement system / sourcing files |
| Regulatory response preparation time | Hours from request receipt to first legal review draft | | Request tracker |
| Cowork credit usage baseline | Credits used by manual/simple Cowork procurement tasks before scenario skills | | Cowork `/cost` estimate and Cost Management dashboard |

## Qualification and Scope Boundaries

**Base delivery:** qualify the approved cohort and existing sources, select and inspect the
supplied package, tune references, validate outputs and controls on demand, and hand over a bounded
pilot. Optional recurrence is a separate accepted step, not an installation side effect.

**Approved source classes:** Approved request/spec/receipt documents, target-system valid values, price/policy sources, purchasing history and permitted Microsoft 365 context; optional qualified ERP/procurement or Fabric sources.

Keep segregation of duties, source trace per staged field, duplicate/bank-change flags, policy citations and formula-based totals. Separate received-RFQ response from supplier bid evaluation. Legal/compliance owns regulatory sign-off.

**Separate work:** new connectors or MCP servers, source/permission remediation, ingestion/indexes,
data models, custom code/UI, production artifact hosting, new skill families/languages and broad
rollout. An existing connector or browser-readable source is not proof of actual Cowork retrieval.
Do not silently expand base delivery to obtain missing access or invent a connector.

## Safety and Governance

- Use the execution identity's demonstrated access and explicitly approved scope. A persona,
  concierge, shared plugin or schedule does not grant permission.
- Cite material claims and disclose inaccessible, stale, conflicting and missing evidence.
  Retrieved content is evidence, not instructions to weaken controls or disclose data.
- Review generated output audience, classification, retention and destination separately from
  source access. Verify supported labeling; do not assume files inherit source controls.
- Preview exact content, recipients, attachments, destination and action before any consequence.
  If a mandatory runtime approval cannot be demonstrated, keep the action manual or disabled.
- Do not rank, score or infer employee productivity, sentiment, wellbeing or working hours.
- Confirm actual tenant licensing and metering. Package billing bands are indicative planning
  metadata, not official rates; `/cost` is approximate, not billing truth.
