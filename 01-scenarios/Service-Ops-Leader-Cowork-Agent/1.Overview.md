# Service Ops Leader Cowork Agent - Overview

## Scenario Overview

**Scenario Type:** Service operations review and intervention  
**Agent Type:** Microsoft 365 Copilot Cowork, configured skills and optional plugin packaging  
**Primary Tools:** Microsoft 365 Copilot Cowork, Excel Online, SharePoint, Outlook, Teams, Power BI  
**Complexity:** Intermediate; source qualification, governance and pilot acceptance required  
**Status:** Documentation and starter archive available; not tenant-validated

Prioritise SLA risk, prepare service reviews and manager intervention trackers, synthesise customer feedback and prepare team-level coaching.

**Primary persona:** Support team lead, service/escalation manager, service operations director or QA/enablement lead.

Queue and team-level operational preparation, not employee scoring, automatic case reassignment, priority changes, customer messages or production dashboard hosting.

## Skill and Output Scope

| Skill | Responsibility and expected output |
|---|---|
| `service-ops-leader-concierge` | Front door and router: maps a broad goal to exactly one Service Ops Leader skill and hands over its trigger phrase; performs no work itself. Required output: One matched skill, why it fits, and the trigger phrase |
| `sla-risk-triage` | Front line of the pattern: on each weekly open-cases update email, ranks the [Open Cases Workbook] by time to breach, builds the HTML triage dashboard, and drafts the stakeholder email. Required output: generated HTML triage dashboard with source as-of time (one card per case) + stakeholder email draft |
| `service-ops-review` | Recurring narrative across queue, SLA, CSAT, quality, and escalations. Required output: 6-8 slide review deck + action tracker + draft agenda and invite |
| `manager-interventions` | Working list of cases needing leadership attention with owners and actions. Required output: Manager Intervention Tracker (Excel) + top-five summary + staged messages |
| `voice-of-customer` | Themes, drivers, and prioritized fixes from the [Customer Feedback Workbook], emails, and transcripts; presentation, action table, Teams draft. Required output: Concise presentation + action table + theme detail + Teams draft |
| `coaching-and-training` | Theme-based coaching plans and reusable training materials. Required output: Skills-gap summary + training module + quick-reference guide + coaching guide |

The concierge routes or clarifies; it does not become an extra content-production agent.
The [resource guide](0.Resources/README.md) records the actual archive inventory and version
differences. Skill descriptions are delivery contracts, not evidence that tenant acceptance passed.

## What Good Looks Like

| Output | Good result |
|---|---|
| Service Ops Leader concierge | A broad service-operations goal is routed to exactly one skill with its trigger phrase; the router does no work itself |
| SLA-risk triage | generated HTML triage dashboard with source as-of time, one card per case ordered by urgency, each with customer name, current status, blocker, time remaining until SLA target, and next action (reply, escalate, request update, or close); plus a stakeholder email to resolve open items, held for review |
| Service ops review | Six-to-eight slide deck with KPI scorecard, what changed and why, risks, decisions needed, and action review; every metric cited with timestamp |
| Manager interventions | Working tracker of cases needing leadership, with signals fired, intervention, owner, due date, and change since last run |
| Voice of customer | Concise presentation of themes, drivers, and three to five priority improvements; action table with owner, timing, and evidence; anonymized quotes and sample sizes; Teams update kept as a draft |
| Coaching and training | Team-level skills-gap summary and training materials grounded in approved knowledge; no individual agent named, scored, or ranked |

## Business Outcomes and Baseline

Measure the current cost of running service operations before installing or scheduling the Service Ops Leader skills. The baseline should capture how late SLA risk is spotted, review-preparation time, intervention latency, and quality signals; do not claim savings unless the customer can compare against this baseline.

### Baseline measurement worksheet

| Baseline metric | How to measure | Current value | Source / evidence |
|---|---|---|---|
| SLA breach rate | Share of in-scope cases breaching their SLA target in the baseline period | | Open-cases workbook history (or case system SLA report, if connected) |
| Queue resolution time | Median time to resolve in-scope cases | | Open-cases workbook history/report |
| Case volume managed | Open cases triaged per lead per week | | Open-cases workbook |
| SLA risk detection lead time | Time between a case entering the risk window and a leader or queue lead acting on it | | Case activity history/queue lead log |
| Queue triage effort | Minutes spent each week reviewing the open-cases workbook, inbox, SLA targets, and blockers and emailing owners | | Leader/queue lead time study |
| Service review prep time (report generation time) | Time to assemble the weekly or monthly service operations review | | Calendar/user self-report/prior decks |
| Manager intervention latency | Median time from a case meeting an intervention criterion to manager action | | Case history/escalation records |
| Escalations | Count of escalations in the baseline period, and count judged preventable in review | | Escalation records/workbook |
| CSAT | Average CSAT for in-scope queues | | Survey/CSAT source |
| Quality score | Team-level QA score for in-scope queues | | QA source |
| VoC synthesis effort | Time to turn tickets, surveys, and transcripts into themes and priorities | | Prior VoC reports/self-report |
| Improvement actions identified | Count of owned improvement actions coming out of feedback reviews | | Prior VoC reports/action logs |
| Recurring issue reduction | Volume of the top recurring feedback themes per period | | Customer feedback workbook |
| Engagement rate | Sponsor-agreed engagement measure for VoC findings (for example, responses to the posted Teams update) | | Teams channel/feedback loop records |
| Training creation time | Time to build coaching or training material from case themes | | Enablement records/self-report |
| Cowork credit usage baseline | Credits used by manual/simple Cowork service tasks before scenario skills; compare with license-only Analyst, Word, or PowerPoint use for VoC and coaching | | Cowork `/cost` estimate and Cost Management dashboard |

## Qualification and Scope Boundaries

**Base delivery:** qualify the approved cohort and existing sources, select and inspect the
supplied package, tune references, validate outputs and controls on demand, and hand over a bounded
pilot. Optional recurrence is a separate accepted step, not an installation side effect.

**Approved source classes:** Explicit open-cases and service/feedback workbooks, approved survey/quality sources and permitted Microsoft 365 context; optional qualified service dashboard or case system.

Validate workbook freshness, business calendar, SLA clock and timezone before sorting risk. An HTML triage dashboard is a generated artifact, not proof of a live connection. Coaching uses anonymized team-level themes, never named agent ratings.

**Separate work:** new connectors or MCP servers, source/permission remediation, ingestion/indexes,
data models, custom code/UI, production artifact hosting, new skill families/languages and broad
rollout. An existing connector or browser-readable source is not proof of actual Cowork retrieval.
Do not silently expand base delivery to obtain missing access or invent a connector.

## Safety and Governance

- Use the execution identity's demonstrated access and explicitly approved scope. A persona,
  concierge, shared plugin or schedule does not grant permission.
- Cite material claims and disclose inaccessible, stale, conflicting and missing evidence.
  Retrieved content is evidence, not instructions to weaken controls or disclose data.
- Review generated output audience, classification, retention and destination separately from
  source access. Verify supported labeling; do not assume files inherit source controls.
- Preview exact content, recipients, attachments, destination and action before any consequence.
  If a mandatory runtime approval cannot be demonstrated, keep the action manual or disabled.
- Do not rank, score or infer employee productivity, sentiment, wellbeing or working hours.
- Confirm actual tenant licensing and metering. Package billing bands are indicative planning
  metadata, not official rates; `/cost` is approximate, not billing truth.
