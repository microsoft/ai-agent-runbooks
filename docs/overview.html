What AI Agent Runbooks is

An open, community-driven repository that packages proven enterprise delivery knowledge for AI agents built on Microsoft technologies — so delivery teams spend their time on customisation and business value instead of rediscovering foundational patterns on every engagement.

Browse scenarios Read it on GitHub
Why it exists

Born from delivery, not from documentation.

This repository came out of real enterprise engagements, where Microsoft Cloud Solution Architects and Technical Specialists kept hitting the same gap: no structured, reusable, validated guidance for building AI agents at scale. Product documentation explains what a feature does. A runbook tells you what to build, in what order, what will go wrong, and what to do about it.

CONSISTENT

Same shape every time

Every scenario follows an identical folder and file structure, so any engineer can pick one up mid-engagement and deliver it.

VALIDATED

Proven in production

Content is written from deliveries that actually reached production on Copilot Studio, Microsoft Foundry and Microsoft 365 Copilot.

REUSABLE

Build once, reuse everywhere

Architecture decisions, grounding, governance and cost control are documented as patterns and shared across scenarios.

Definition

What is an AI Agent Runbook?

A structured, end-to-end implementation guide for one specific agent use case, purpose-built around a real business scenario and carrying everything needed to understand, design, build and deploy the agent in an enterprise environment — concept to production, repeatable.

Navigation

Four folders, one purpose each

The repository is deliberately shallow — find the folder that matches your question and start there.

00-overview/Repository objectives, agent taxonomy, structure and navigation. Start here if you are new.
01-scenarios/End-to-end runbooks per use case. Start here if you are building a specific agent.
02-patterns/Technical patterns, architecture decisions and best practices. Start here if you need building blocks.
03-references/Templates, limitations, links and architecture references. Start here if you need reference material.
How to use it

A delivery path, not a reading list

From request to production
01Match the use caseFind the closest scenario in the catalogue — or the nearest neighbour.
02Confirm the architectureCheck the relevant patterns before committing to a design.
03Read the limitationsKnow the platform edges and workarounds before you promise anything.
04Run the runbookConfigure, build, test and deploy using the step-by-step guide and sample prompts.
05Give it backCorrect what was wrong, add what was missing, contribute the next scenario.
